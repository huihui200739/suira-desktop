# 0.2.4 发布前检查

日期：2026-10-31。环境：Windows 11 x64，系统构建 26300，Electron 45.0.0，当前显示器 150% 缩放。

**结论：已完成本环境的自动化回归与独立安装生命周期验收，产物作为发布候选准备。尚未创建 GitHub Release。** 不能把单机验收解释为所有电脑上绝不会遇到问题。

## 本次修正

- 全局快捷键需主动开启，移除注册冲突时绕过占用的底层按键监听。保护 Ctrl+字母/数字与系统组合键，固定专用唤起键优先级。
- 启动及设置页检查本软件键位的全局注册占用，保留输入框和输入法优先的面板交互；说明检测范围与全局模式对菜单键的影响。
- Markdown 安装候选、文件参数路由、原文件主动保存、加密草稿恢复及外部修改保护。
- 安装器进程检测宏保留调用方寄存器并清除遗留错误标记。
- 诊断报告区分未启用的键位配置与实际注册；发布包排除测试页面和旧键盘监听代码。
- 更新产品图、版本说明、快捷键与文件打开方式指南。

## 发布时仍需说明

1. Windows 没有统一扫描所有应用内部快捷键或让随序“最高优先级”的机制。注册占用与应用菜单键不同，用户开启全局模式后可能遮蔽菜单 Alt+字母操作。[详细规则](SHORTCUTS-AND-MARKDOWN.md)
2. 默认 Markdown 应用由用户通过 Windows「打开方式」或设置页选择。安装器仅提供候选，不替换当前选择。
3. 当前安装包未使用发行者证书签名，可能出现 Windows 未知发行者或 SmartScreen 提示。
4. 此前实机升级写入失败与安装阶段长时间卡顿的完整根因尚未确认；本轮独立产品测试未复现，不能宣称历史问题已经彻底修复。[脱敏调查](install-freeze-investigation.json)
5. 此次不是多台干净电脑的兼容认证；其他 Windows 构建、杀毒软件、输入法、多屏和 DPI 组合仍需实际用户反馈。

测试使用独立临时资料和虚构内容。用户当前安装、个人数据、密钥和此前备份均保留；完成后运行仓库清理脚本并核对 GitHub 分支提交。
