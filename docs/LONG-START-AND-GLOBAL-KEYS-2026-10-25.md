# 长截图启动修复与全局面板键

## 修复的问题

此前长截图收起截图覆盖层后只等待 70 ms，依赖当时的前台窗口；选区中的实际应用未必已取得焦点，第一帧也可能仍有 Windows 收起动画的遮罩。启动失败后重新发送 `capture:shown` 又会清空选区，盖掉具体错误，看起来一直在要求重新框选。此前替换前台窗口与采集适配器的 IPC 测试没有覆盖这条真实桌面交接链。

现在使用选区中心的物理坐标命中实际窗口，以 HWND/PID/进程启动时间验证并激活；连续三帧稳定后才建立拼接基准。失败时恢复原覆盖层与选区，显示具体原因，可直接重试。普通截图仍保留原有快速流程。

## 全局键位

所有已实现工具及自定义应用、文件、文件夹、网页绑定都派生 `Alt + 对应键`，不需要先打开悬浮板。默认示例：`Alt+C` 截图、`Alt+V` 剪贴板、`Alt+G` 长截图、`Alt+O` 提取文字、`Alt+N` 速记。面板内单字母直达仍保留。

拖动或改绑后，旧组合键立即释放、新键注册后与面板配置一并保存。注册被占用或落盘失败则整体回滚。未绑定及未实现键不注册。键帽提示展示对应全局组合键及注册失败原因。

截图/剪贴板设置中的额外专用组合键保留，与相同 Alt 键共用注册，避免重复抢键。若用户把内容绑定在 S/E/H，面板唤起、布局轮换和钉图显隐会让到 Alt+F1/F2/F3 等空闲功能键；设置页展示实际生效值。F 上的内容优先于旧版 Alt+F 兼容面板入口。

## 验证

- `node test-long-start.js`：实际命中窗口、激活失败、焦点被抢、遮罩首帧剔除及持续不稳定画面拒绝。
- `npm run verify:long-capture`：保留原浏览器排版与逐行像素验证，补充启动失败保留选区；新增独立外部 Electron 测试页面，使用真实前台探针、Windows GDI、DPI 坐标，分别从截图工具栏和面板入口框选、手动滚动、确认高度增加并取消。原生桌面测试不保存或发布桌面画面。
- `node test-panel-shortcuts.js`：全键生成、空位/占位不抢键、移动、辅助键让位、系统占用和保存失败的回滚。
- `npm run verify:panel-global`：调用真实注册回调和主进程执行入口；仅在独立测试实例中替换实际锁屏、启动外部程序等副作用，验证各工具派发、自定义内容、换位、F/S 冲突及失败回滚，不锁定用户桌面或打开外部网址。

长截图仍由用户手动向下滚动，停稳后自动拼接。算法对动态内容、改变布局的虚拟列表和重叠不足画面仍会暂停提示，范围与原用法文档一致。
