# 长截图：透明框选与后台激活限制修复

用户在当前聊天页面框选后收到“无法激活选中的窗口”。此前由后台原生组件调用 `SetForegroundWindow`，再把激活成功作为长截图的前置条件；这不符合 Windows 的前台权限限制。旧版置顶测试窗口也没有充分覆盖普通窗口。

## 本次行为

- 长截图启动不再调用 `focusTo`，不注入按键或点击。使用选区命中的窗口句柄、PID、进程启动时间验证实例，原生 GDI 采集可见区域。后续按选区的可见源校验，不要求它始终抢到前台。
- 选区被其他窗口覆盖、窗口移动/尺寸或页面标题变化时暂停。工具条与选区重叠时，源探针避开工具条；采集帧仍排除工具条。
- 从面板 G / Alt+G / 工具箱 / 搜索进入，直接显示预热的透明框选层。该窗口不激活、不绘制整屏截图，不经过整屏采集、PNG 解码和普通截图加载流程；先显示框选层，再收起原面板。
- 拖动框选后开始采集；最小尺寸、单屏范围等验证保留。Esc、右键或“取消”退出框选；失败保留选区，可按“重试”直接继续。取消会停止正在启动的区域采集组件，过期提交不会启动新会话。
- 普通截图工具栏上的长截图继续沿用已有选区；普通截图、标注和图片编辑的流程不改。

## 验证与边界

`npm run verify:long-capture`：

1. 原生 Windows 区域组件连续 PNG 协议。
2. 独立 Electron IPC / 浏览器页面逐行像素校验、取消、失败重试、非前台可见源、过期提交；测试中禁止 `focusTo`。
3. 独立**普通、非置顶、带标题栏**的外部窗口，真实 HWND 查询、DPI 映射及 GDI 帧。分别验证普通截图工具栏、直接长截图框选入口；记录采集源 PID，确保真的是测试窗口，而不是其他前台窗口。后台激活函数被设为抛错，验证采集完全不依赖它。两条链路滚动后高度由 570 增至 720 像素。
4. 直接入口断言没有调用整屏采集。预热测试实例中，入口到透明框选就绪实测约 7 ms；这是该测试环境的结果，不代表所有设备的延迟保证。

`node test-long-start.js` 验证无需后台激活、拒绝失效窗口、探针避开工具条、稳定首帧；原有拼接与会话测试继续保留。

不通过 UI 自动化操作用户的聊天页面，不发送测试内容，不保存或发布原生桌面画面。仍由用户手动向下滚动，画面停稳后自动拼接；动态内容、改变布局的虚拟列表和缺少可辨认重叠的页面仍可能暂停提示。
