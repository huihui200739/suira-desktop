# 0.2.29 任务匣与文字阅读

方向：随序把截图、文字和链接收进同一件事；性格是安静、直接、可靠；材质来自桌面索引与纸面内容；视觉重点是用户收集的真实内容；保留按顺序收集和整理的轨迹细节。

审视旧页：页面标题与详情标题重复，大横栏切断任务索引；详情无限横向伸展，少量文字缺少阅读边界；空状态与常用操作分散；文字保留 OCR 的汉字间空格、重复空行，再叠加 1.85 行高，导致卡片难以扫读。

本版将任务标题、新建按钮和筛选集中在索引栏。详情以限定宽度的白色内容面承接任务标题、操作和收集内容。短空状态仍居中在右侧内容区，填入内容后使用连续、紧凑的条目排版。浅色与深色沿用同一组语义变量。

参考 [Linear 的分组、显示属性与视图说明](https://linear.app/docs/display-options)、[Todoist 的列表与看板布局](https://www.todoist.com/help/todoist/features/use-the-board-layout-in-todoist-AiAVsyEI)。采用的是信息集中、可扫读和按上下文呈现操作的原则，没有复制产品品牌。设计审视使用 unslop — Damir Sokolovsky（CC BY 4.0）。

悬浮板误收起来自指针助手坐标与 Electron 窗口坐标混用：助手可能受到 DPI 虚拟化，再调用 screenToDipPoint 会二次换算。现在读取 Electron 的 getCursorScreenPoint，与窗口 getBounds 使用相同的 DIP 坐标。测试故意提供错误的助手坐标，同时分别提供面板内外的 Electron 坐标，验证三点菜单保持展开、外部按下正确收起。原生失焦处理在下一个事件循环核对窗口焦点，保留真实失焦收起。

OCR 在服务输出端整理重复空行、汉字之间的识别空格，保留正常分行、英文词界、链接和代码缩进；缓存也返回相同整理结果。已有记录仅在卡片、任务条目和全文预览时整理显示，不批量修改数据。复制原文保持原始文本，紧凑复制仍是显式操作。识别框行高 1.5，内容卡片和全文预览为 1.55，均使用正常字距。

验证：138 项 UI 接线、71 项真实浏览器渲染、102 项截图覆盖层检查、16 项 OCR 检查、文字整理与 OCR 缓存测试、安全检查，以及完整键位绑定／菜单／拖动／缩放检查通过。utility-tools-0.2.29.json 记录菜单实际点击、DPI 坐标、外部点击、原文保留与任务布局检查；panel-reveal-0.2.29.json 记录冷／热／重建显示与取消操作。安装包 118 个源码文件逐字节匹配，CRC、更新清单与摘要通过。界面截图只包含虚构测试资料。
