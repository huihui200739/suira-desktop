# 0.2.15 桌面透明合成与显示模式验证

0.2.14 的网页截图 alpha 检查只验证了 Chromium 页面，未覆盖 Windows 最终合成，因而漏掉了实际桌面上的白底问题。本轮已复现并修正，不能将此前的网页检查当作桌面透明验证。

## 原因与修复

小悬浮板创建为透明 HWND 后，又调用了 `setBackgroundMaterial('none')`。在当前 Electron 45 / Windows 环境中，这次设置会覆盖透明合成，使桌面呈现不透明白底。小面板现在保留创建时的透明合成，不再执行这次材质重置。页面原有浅底、高光、键帽、文字以及原生圆角继续保留。

显示模式以前只改变当前窗口，并在每次唤起时强制使用窗口模式。现在显式选择窗口／全屏会写入设置，唤起、关闭重开和重启按保存值恢复。快捷键作为显示／隐藏开关，不再强制切回小面板。Esc 临时返回窗口不覆盖显式选择。

## 验证

- `npm test` 完整回归通过。
- `npm run verify:launcher` 验证全屏偏好落盘、隐藏与快捷键重开、重启恢复全屏，以及改选窗口后的恢复。
- `node tools/panel-composition-check.js --screenshots`：实际桌面放置独立受控背景，以原生屏幕 DC 取样。旧实现面板上两次均为 `[250,251,252]`；修复后红底为 `[180,53,69]`、蓝底为 `[52,96,182]`。面板隐藏后的背景分别为 `[176,32,48]` 和 `[32,80,176]`。测试证明颜色来自实际后方窗口，未采集用户桌面内容。
- [红底实拍](product/panel-desktop-red.png)、[蓝底实拍](product/panel-desktop-blue.png)通过原生 BitBlt 生成，范围仅包含面板和受控背景。
- `npm run screenshots` 检查独立窗口、真实圆角、最大化恢复及任务栏边界。
- `node tools/release-package-check.js` 检查 94 个应用文件与包内字节一致、更新配置和安装包校验元数据匹配。
- `node tools/packaged-markdown-check.js` 验证实际安装包中的显示模式保存与重开、文档打开保存及窗口稳定性。
- 已发布 0.2.15；匿名更新检查、完整下载安装包与 SHA512 校验通过，当前版本检查返回已是最新版。

该修复不通过截屏壁纸、降低整个窗口文字透明度或取消原生圆角模拟效果。
