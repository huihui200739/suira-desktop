# 真机验证清单

日期：2026-10-22。用途：在本机 Windows 上跑一遍，把结果反馈回来。

**为什么需要这份清单**：开发环境无法启动 Electron GUI（实测退出码 `0x80000003`
STATUS_BREAKPOINT），所有验证都只做到「代码 + 无头 Chrome 渲染」层面。
下面这些必须在真实窗口里点过才算数。

---

## 第 0 步：准备（约 2 分钟）

### 0.1 打开一个干净的终端

用 **PowerShell** 或 **CMD**，不要用正在跑其它 Electron 工具的终端。

### 0.2 先确认没有 `ELECTRON_RUN_AS_NODE`

这个环境变量会让 Electron 以 Node 模式启动，**窗口不会出现**。
2026-10-22 实测：带着这个变量启动会直接报
`TypeError: Cannot read properties of undefined (reading 'setName')`。

```powershell
echo $env:ELECTRON_RUN_AS_NODE
```

- 输出为空 → 正常，继续
- 输出 `1` → 执行下面这行清掉（只影响当前终端）：

```powershell
Remove-Item Env:\ELECTRON_RUN_AS_NODE
```

> 新版已把这个报错换成中文说明，看到「检测到环境变量 ELECTRON_RUN_AS_NODE」
> 就是没清掉，重做一次即可。

### 0.3 进入项目目录并启动

```powershell
cd 'C:\Users\huihui\Desktop\截图工具'
npm start
```

**预期**：主窗口出现，右下角托盘出现随序图标。

如果没出现窗口，先跑自检（见第 3 节），别急着逐项测。

### 0.4 怎么判断「真的启动了」

**不要只看截图或窗口有没有闪一下**，看数据目录是否被创建：

```powershell
Test-Path "$env:APPDATA\随序"
```

| 结果 | 含义 |
|---|---|
| `True` | 应用真的启动过，数据目录已建立 |
| `False` | 从未成功启动 —— 按第 3 节排查 |

应用只要成功启动一次，就一定会创建这个目录。

## 第 1 步：先跑自检（推荐）

自检会生成一份环境报告，比逐项试错快得多。

```powershell
npm run diag
```

跑完后报告会写在：

```
C:\Users\huihui\AppData\Roaming\随序\diag-report.txt
```

**把这个文件的内容发给我**，我就能判断问题出在哪一层（环境、权限、快捷键占用、
显示器、OCR 引擎还是数据目录）。

自检**只读**：不改设置、不动你的数据。

## 第 3 步：如果窗口起不来

按顺序试，把每一步的输出发我：

### 3.1 确认环境变量

```powershell
echo $env:ELECTRON_RUN_AS_NODE
```

必须是空的。

### 3.2 直接用 electron 启动，看真实报错

```powershell
cd 'C:\Users\huihui\Desktop\截图工具'
.\node_modules\electron\dist\electron.exe .
echo "退出码: $LASTEXITCODE"
```

常见退出码：

| 退出码 | 含义 |
|---|---|
| 无输出、立刻返回 | 见 3.1，多半是环境变量没清 |
| `1` + 中文说明 | 新版会直接告诉你原因，照着改 |
| `-2147483645`（`0x80000003`） | STATUS_BREAKPOINT。开发环境里出现过，属沙箱限制；真机上若出现请告诉我 |

### 3.3 换一个数据目录（排除用户数据损坏）

```powershell
.\node_modules\electron\dist\electron.exe . --user-data-dir="C:\temp\suira-test"
```

如果这样能起来，说明原来的数据目录有问题——把
`C:\Users\huihui\AppData\Roaming\随序` 改名备份后再试。

### 3.4 检查是否有残留进程

```powershell
Get-Process | Where-Object { $_.Name -like '*electron*' -or $_.Name -like '*随序*' }
```

有的话先结束掉（单实例锁会让第二次启动直接退出）。

## 反馈什么给我

最省事的方式：**先发 `diag-report.txt` 的内容**，再发下面三项。

1. **哪几项不对**：只报编号即可（如「3、9、17 不对」）
2. **具体现象**：每项一两句话，比如「按 O 松手后没反应，要手动点识才行」
3. **有没有报错弹窗**：有的话截个图或把文字发我

如果一切正常，直接说「全过」就行——我会把 README 里的「未验证」表逐项改成已验证。
