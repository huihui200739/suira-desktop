# 四角、应用图标与底部剪贴板入口

## 四角底板

复现条件：Windows 150% 缩放，透明 BrowserWindow，CSS 24 DIP 圆角，原生窗口已有 HRGN 裁切，同时启用 DWM acrylic。

GetWindowRgn 确认角落已经在原生区域之外，但桌面合成截图的四角仍为灰色 `[209,209,209]`，与后方测试底色 `[205,40,199]` 不同。仅检查 CSS border-radius 或 setShape 参数不足以发现这个问题。

动作面板和剪贴板横栏改用原生透明背景 `setBackgroundMaterial('none')`，保留页面透光材质和原生区域裁切。文件暂存站的原生逻辑保持独立。修复后四角的实际桌面像素与后方底色一致，窗口主体仍可见。该实现不再声称这两个浮层使用系统 acrylic 桌面模糊。

验证：`node tools/native-corners-check.js`。测试会临时显示不同底色的背景窗口，结束时销毁；不修改壁纸、系统主题或用户内容。

## 应用图标

原来直接对 `.lnk` / `.url` 调用 getFileIcon，读到了文件类型的白纸与地球图标。

- `.lnk` 通过 readShortcutLink 读取指定图标、资源索引和实际目标。
- `.url` 只解析本地 IconFile / IconIndex，支持 UTF-8、UTF-16 和环境变量路径；不访问 URL、不启动应用。
- EXE / DLL 图标资源在一个短生命周期的本机助手中批量提取；正确释放 HICON。提取失败时读取目标程序图标，仍无法取得则保留名称首字作为回退。
- 成功结果缓存，失败结果允许重试。同一批请求复用在途任务。
- 助手随源码打包，复用现有 .NET Framework 编译机制；不可用时回退，不阻止应用面板打开。

实机首屏：28 项图标全部加载，27 个不同图像来源。验证：`node test-app-icons.js` 与 `node tools/app-icons-live-check.js`。

## 剪贴板入口

- 默认全局组合键：Ctrl + Alt + V（可在设置中改键）。
- 动作面板 X 键以及右下角「剪贴板」按钮都打开底部横栏。
- X 键此前指向主窗口内容库，现已更正执行语义和提示文案。
- 横栏仍可通过「内容库」进入完整历史界面。

实机验证确认按钮和 X 键均使原生 clipboardbar 窗口可见；读取现有历史，不复制、收藏或删除条目。

## 验证结果

完整 npm test 通过；另做真实桌面四角像素对比、真实应用图标与入口检查。预览和实际窗口均保留方形键位、正式图标及去除底部内容条的布局。
