# 唤起延迟与剪贴板历史粘贴

## 行为

- 单击历史卡片，复制选中内容、立即收起底部栏并粘贴到唤起前的输入框。
- 系统剪贴板保留选中内容，再按 Ctrl+V 仍粘贴同一条记录。
- 图片复制为真实位图；复制失败时保留面板并显示错误。
- 历史条的点击与 Enter 是显式粘贴操作，不受通用「复制后返回粘贴」默认关闭设置影响。

## 延迟来源与修改

- 前台助手此前启动时固定等待 4 秒再发 ping。改为立即发送，助手就绪即响应。
- 预编译、预热原生前台助手，复用进程查询、校验、恢复焦点和发送 Ctrl+V，避免每次启动 PowerShell 与 Add-Type。编译不可用时保留 PowerShell 兼容路径，焦点恢复不再同步阻塞主进程。
- 先记录输入目标，再显示浮层；提交时不会误把自己的浮层当成原目标。原生助手在注入前再次检查窗口、PID、启动时间和实际焦点。
- 动作面板、剪贴板条和截图覆盖层提前加载并保留页面，取消其闲置销毁。动作面板失焦分支也统一走同一隐藏入口。
- 截图收起仍立即清空图像与画布缓冲。单屏原图与裁剪共用一次解码，多屏直接使用合成画布，省去整张桌面的再次 PNG 编码和解码。
- 仅在有自己的可见窗口需要隐藏时等待桌面合成，不再每次截图固定等待 40 毫秒。

## 验证

- `npm test` 全部通过；后续新增原生助手、单屏解码、多屏拼接与像素检查也已通过。
- 真实 Electron、独立临时数据目录和本地测试输入框验证单击粘贴、底部栏收起、再次 Ctrl+V、截图可操作以及画布释放。不会向真实聊天发送消息，测试后恢复原系统剪贴板。
- 一轮真实测试：剪贴板可操作 39 / 20 / 21ms，动作面板 35 / 25 / 30ms，截图 311 / 191 / 214ms。时间包含 IPC、原生采集与页面加载画面的等待，数值随屏幕和系统负载变化。
- 65 秒闲置测试：三个高频入口保留原窗口，剪贴板再次唤起 16ms。
- 单独验证历史图片复制后的系统 PNG 位图，尺寸及全部像素与历史原文件一致。

复验命令：`npm run verify:latency`。该测试需要可用的交互桌面，并允许本地测试输入框获得焦点；Windows 阻止后台置前时会明确报告焦点不匹配，避免把测试文字粘入其他应用。仅检查位图复制可运行 `node tools/latency-live-check.js --clipboard-image`。
