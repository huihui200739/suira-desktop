# 长截图启动与拼接修复（2026-10-27）

## 问题与改动

用户反馈框选后画面闪一下，又回到原选区，长截图无法开始。代码中这条路径是：隐藏框选层 → 准备目标/首帧失败 → 恢复选区。仅凭这段描述，不能断定是哪一个底层错误。

本次修复覆盖了可复现的启动阻断：

- 首帧原来要求连续三帧变化小于 0.15%，小型动画即可持续阻止启动。现在允许最多 2%、局限在 8×8 网格中四格内的变化；同样的局部变化也不会在启动后误触发拼接失败。跨区域滚动和整屏动画仍等待停稳。
- 框选层隐藏后的旧窗口命中会重试，不再把无关的前台窗口当作选区来源。PowerShell 兼容探针补齐按物理坐标命中和窗口边界。
- 原生组件初始化失败后，用户重试可以重新准备组件。首次区域采集等待 12 秒，后续请求仍是 4 秒；错误保留编译器、进程及协议原因，并标注失败发生在组件准备、窗口识别、首帧等待或工具条显示。
- 采集前后都验证来源，暂停/继续前的在途帧会丢弃。
- 原拼接器把固定页眉/页脚限制在选区的 28%/22%，较高聊天输入框会污染重叠匹配甚至重复入图。现在依据连续静止边缘的实际范围排除，并保留至少 96 像素正文用于对齐。补齐一像素微滚动。

## 浮引的 REA 静态研究

本机目标为浮引 6.0.1 (216)，arm64 切片 SHA-256：`994fea714090a8a2ee1aaedea5a40ef1789d41f281f87c948eb20502062c1307`。REA Mach-O 证据 ID：`ev_189b1a2bb80552f14082eb3e0c24acade79261d72f1cdbe1250748f5622e7485`。原始证据保留在本机 `research/long-capture-rea/`，第三方二进制与反汇编不提交进本仓库。

实际机器码可确认：

- 初始化器 `0x101849948` 设置最小采集间隔 0.15 秒、停稳延迟 0.18 秒和最大高度 30000 像素。
- 工作函数 `0x1016ed1c8` 裁切两幅 CGImage，创建 `VNTranslationalImageRegistrationRequest` 与 `VNImageRequestHandler`，执行请求，再读取平移配准结果的 `alignmentTransform`。
- 另有行特征路径：`0x1016f00b8` 按行采样 RGB 均值，`0x1016ed6f8` 搜索整数位移，并通过误差、纹理量及相对改善门槛排除不可靠候选。
- 控制器元数据包含固定顶/底区域、左右边缘裁切、前一帧、累积画布及滚动活动代数等独立状态。字段存在本身不能证明完整运行时序。

据此采用采集、稳定判定、对齐、固定带处理、累积输出分开的实现思路。Windows 代码独立实现；Apple Vision API 不能直接移植。这里未宣称恢复原始 Swift 源码，也未复刻原版所有自动滚动、横向滚动或后备策略。

本轮 Ghidra 伪代码进一步印证上述路径：Vision 工作函数证据 `ev_75cfdead87fd898e46cfff7545c9d5ae5b85c403ed1b06c1bb8a8bd22a7aa406`；行特征生成证据 `ev_a3fa2ba3e697dc2f9e8051653d0572ddcb87a27aa50e842ae2effe75f01f2faf`；后备位移搜索证据 `ev_7cdbba1535da292a6e89b6787255351ea522a27d20d21168a2fa40ab797c2dea`。反编译器的类型恢复与间接调用覆盖仍有局限，不能据此声称原版全部路径已还原。

## 验证

`npm run test:long-capture` 覆盖首帧局部动画、隐藏后的旧命中、反向/重复/无重叠画面、固定输入框、会话取消与来源切换、原生通信故障。

`npm run test:long-browser` 使用真实无头 Chrome/Edge、生成的文字页面和 28/140 像素固定输入框，在 100%、125%、150%、200% 缩放下连续滚动三次；100%/200% 还与一次完整高度的浏览器渲染逐像素比较。该检查需要 Node.js 22+ 与 Chrome/Edge，可通过 `SUIRA_CHROME` 指定路径。`pngjs` 补为显式开发依赖。

新增手动运行的 `Long capture Windows regression` GitHub Actions，执行上述回归和 `npm run verify:long-capture`。原生验证只使用生成的外部测试窗口，检查真实 Windows helper、GDI、Electron IPC、两个框选入口及取消流程；不采集用户聊天内容。可通过 `SUIRA_ELECTRON` 指定测试 Electron。

Mac 本地的长截图回归、八组浏览器用例以及前台探针、坐标、安全、UI 接线检查通过。完整 `npm test` 本地在 OCR 资源检查处停止：新克隆缺少 Git LFS 实体，语言包仍是指针；部分其他脚本也仅支持 Windows。因此不把 Mac 本地结果称作完整 Windows 实机验收。

2026-10-28 补充：提交 `9f9bb61` 的 [Windows CI 验证](https://github.com/huihui200739/suira-desktop/actions/runs/40619454055) 全部通过，包括真实 GDI 区域组件、Electron IPC、普通外部窗口的两个入口、滚动增长和取消。运行环境为 Windows Server 2025；尚未直接操作用户那台 Windows 电脑。首次 CI 暴露 Electron 45 按需下载的差异，因此验证命令现在显式运行其安装器，再执行原生测试。

Windows 更新后需重新启动应用，使用 `git pull` 拉取的代码运行；已打包的旧安装包不会自动包含本次修复。用法仍是 `Alt+G` 框选，随后在原页面手动向下滚动，停稳自动拼接，点击完成进入编辑预览。
