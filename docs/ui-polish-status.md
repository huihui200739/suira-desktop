## 原生模糊实验与最终实现

在独立测试配置中启用 Electron `setBackgroundMaterial('acrylic')`，以模拟消息窗口和红、蓝纯色窗口作为背景，不读取用户桌面内容。背景文字得到柔化，但系统材质渲染进入了当前原生裁剪区域以外的圆角。

蓝色背景为 RGB `(32, 80, 176)`。同一受控截图的圆角外像素 `(5, 5)` 在原透明实现下保持背景色；启用系统 acrylic 后变为 `(137, 167, 227)`，因此弃用系统 acrylic 路径。

Electron 的系统材质会覆盖非客户区，且仅支持 Windows 11 22H2 及以后版本，见 [官方 BrowserWindow 文档](https://www.electronjs.org/docs/latest/api/browser-window#winsetbackgroundmaterialmaterial-windows)。

最终实现通过 Koffi 在应用进程内调用 `SetWindowCompositionAttribute` 的 blur 状态，保留原生 alpha 窗口。测试条纹的相邻像素变化量由 13.67 降至 0.12，背景高频细节约减少 99%；圆角外与受控背景的各通道色差小于 25，没有先前的实色底板。详见 [量化记录](native-blur-verification.json)。

该系统接口采用动态加载，遵循 [微软 API 说明](https://learn.microsoft.com/en-us/windows/win32/dwm/setwindowcompositionattribute)。原生模块或接口不可用时保留透明窗口。模块缓存 HWND 和状态，窗口句柄重建后重新应用；全屏、减少透明效果、高对比度和更强遮挡模式下关闭模糊。

## 验证与交付边界

- `npm test`：全套自动化回归。
- `npm run verify:workspace`：保存、导出、重载、编辑模式、目录开关、备注展开，以及窄窗口中窗口按钮可达性。
- `npm run verify:launcher`：应用绑定、菜单、全屏与窗口切换、透明度设置及重启记忆。
- `npm run screenshots`：实际 Electron 窗口截图、原生圆角、缩放及最大化恢复。
- `npm run verify:composition`：受控桌面背景下的实际透色。
- `npm run verify:blur`：同一真实桌面背景，关闭/开启模糊的边缘能量对照与圆角外像素检查。
- `node tools/packaged-material-check.js`：使用独立测试配置启动本机安装版，验证 0.2.17 和四个目标窗口的打包原生模块及设置切换。
