# 文件中转：隐藏式交互与原产品差距

日期：2026-10-23。对照仓库内浮引 6.0.1 build 216 的静态证据，以及当日查阅的[浮引官网](https://fg.vkr.me/)和[官方更新日志](https://fg.vkr.me/mac/changelog/)。未在 macOS 原版中逐项实机操作；官网描述与代码证据不等同于完整行为复现。

## 这轮实际改变

平时真正隐藏窗口并启用鼠标穿透，已有暂存文件、普通鼠标经过或悬停都不会显示胶囊。拖着文件靠近任一显示器工作区顶部中央时，临时启用 440×36 DIP 的接收区；只有 Chromium 收到 `Files` 拖放才展开卡片。普通文字拖拽不会展示卡片。拖离后收起，Esc 一次完全隐藏；主动查看暂存仍可从工具箱或托盘打开。

鼠标状态来自本机系统 API 的只读小型宿主，每 60ms 检查按键与指针，按边沿和拖动位置变化发消息；不安装全局输入钩子，不注入输入，不读取剪贴板。宿主随父进程关闭；编译或启动失败时保持隐藏，仍可通过工具箱/托盘手动打开，诊断中记录失败原因。

修复了两个常驻问题：三态 `mode=sleep` 不再被旧二态 `expanded=false` 改回胶囊；休眠不再靠 CSS 隐去内容而留下挡住其他应用的命中窗口。展开时保留到顶边的拖放走廊，避免窗口下移导致指针突然离开接收区。重复展开也保留闲置回收计时，`showInactive` 的收起判断按实际指针位置而非窗口焦点进行。

同时补齐：

- 热区跟随拖动所在显示器，按各自工作区定位；显示器连接、拔出或缩放改变时先隐藏并重新定位。
- 拖入前检查文件是否存在，准确区分真实文件夹；无效路径不生成假卡片。
- 移除和清空可连续撤销本次运行最近 10 次引用变更；不会复制、移动或删除原文件。退出应用后撤销栈不保留，正常暂存列表仍持久化。
- 拖入失败、重复文件、不可读文件、超出容量都有反馈。容量淘汰仅移除暂存引用。
- 卡片 DOM 不在重复 dragenter 时重建，避免嵌套拖放事件抖动。
- 复制/移动目前仅是偏好记录，UI 说明实际拖放操作由目标应用决定，没有冒充已实现原生移动结果跟踪。

## 与原版对照

官方更新日志列出浮引岛的文件堆叠、锁定、预览、筛选、一键清空和连续找回；6.0.1 另有隔空投放区开关。[来源](https://fg.vkr.me/mac/changelog/)

| 能力 | 当前 Windows 实现 | 后续优先级 |
|---|---|---|
| 按需出现、拖入与拖出 | 本轮改为默认隐藏、文件拖入才展示；原生拖出保留 | 继续人工验证资源管理器、聊天应用的跨进程拖放 |
| 多显示器边缘命中 | 本轮增加按工作区热区选择、屏幕变化回收 | 混合缩放、顶部任务栏、全屏应用实机检查 |
| 移除/清空后找回 | 本次运行内最近 10 次撤销 | 增加持久找回历史与明确保留期限 |
| 文件预览与翻页 | 当前用系统关联应用打开，图片卡片有缩略图 | 高：独立快速预览，区分预览与打开 |
| 筛选、文件堆叠 | 目前是最多 24 条的平铺可滚动网格 | 高：类型/名称筛选、分组与批量选择 |
| 锁定/固定卡槽 | 未实现，容量超出时淘汰最早引用 | 高：固定条目不被容量淘汰 |
| 拖出后的复制/移动结果 | 原生拖出已接线，目标操作结果未跟踪 | 中：确认结果后再处理引用，不凭拖出就删源文件 |
| iCloud、AirDrop 与跨设备 | 无对应实现 | 后续独立设计 Windows 侧跨设备方案 |

产品整体差距还包括：动作键位的用户自定义与直达绑定、应用文件夹及批量排序、通用长截图、完整录屏、系统右键与更多边缘入口。这些仍按既有差距表推进，本轮没有用占位界面宣称完成。

## 验证记录

- `npm test`：全量逻辑、页面渲染和交互回归通过。
- `node test-island-wake.js`：7 组，包括主/负坐标副屏热区、普通指针不唤醒、协议分段、退出/超时、系统 C# 编译、自测及真实 Windows 侦测进程启停。
- `node tools/island-check.js`：103 项，包括普通悬停/文字拖拽保持隐藏、文件拖入展开、离开回收、旧广播不唤醒、Esc 隐藏及撤销按钮。
- 独立数据目录的真实 Electron：`SUIRA_CDP_PORT=9317 node tools/electron-island-check.js`，49 项通过，覆盖真实 preload/IPC、休眠状态、原生侦测就绪、文件/文件夹校验、连续撤销。

自动化覆盖系统侦测进程及 Electron/页面链路，不等同于实际从资源管理器拖入、再拖到第三方应用的整条 Windows OLE 手工验收。多屏几何有自动化覆盖，本轮实机只有当前显示配置。

## 启用

已运行的旧实例需从托盘退出，再执行 `npm start`，新的主进程接收器才会生效。没有改动现有暂存列表，也没有删除用户文件。
