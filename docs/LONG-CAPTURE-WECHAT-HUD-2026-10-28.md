# 长截图：去闪烁、可点击、右下角预览（2026-10-28）

## 用户反馈

1. 点完长截图后工具条一直闪烁，取消 / 继续 / 完成都点不动；
2. 刚点长截图时会先「闪退一下」再出来；
3. 希望像微信原生那样，采集过程中在右下角给一张实时预览图。

截图里的提示是「滚动过快或画面已变化。请回滚到上一段附近，再点继续」，
正好落在「已暂停 + 按钮点不动」的状态上。

## 根因

### 1. 每帧 hide/show 造成的闪烁与点击失效

旧实现担心工具条被拍进长图，当工具条落点与选区相交（`hud.overlap`）时，在每次采集前
`win.hide()`、采集后 `win.showInactive()`。采集间隔 240ms，也就是每秒 4 次隐藏/显示：

- 用户看到的就是持续闪烁；
- 窗口隐藏的那 50–100ms 里点击会落到下层窗口，表现成「点什么都不管用」；
- 工具条本身 `focusable:false`，键盘也无法操作。

### 2. 启动空档

旧顺序是「隐藏框选层 → 识别窗口 → 等首帧（最长约 1 秒）→ 新建 BrowserWindow + loadFile → 显示工具条」。
中间这段时间屏幕上什么都没有，用户看到的就是「闪退一下再出来」。

### 3. 只要对不上就暂停

`unmatched` / `ambiguous` 会立刻暂停采集。滚动过程中对不上本来就是常态，
于是稍微滚快一点就长期停在暂停态，还要用户「回滚到上一段附近再点继续」。

## 改动

### 工具条「看得见、拍不到」

改用 `setContentProtection(true)`（Windows `WDA_EXCLUDEFROMCAPTURE`）。工具条不再隐藏，
采集期间始终可见、可点，也不会出现在长图里。

本机实测（`capture-host.cs` 的 GDI `BitBlt` + `DwmFlush`，150% 缩放）：

| 状态 | 采集到的窗口红色像素 |
| --- | --- |
| 普通窗口 | 271 783 |
| `setContentProtection(true)` | 0（窗口完全从采集结果里消失） |
| 关闭内容保护后 | 271 783（恢复） |

因此 `hud.overlap` 那套 hide/show 逻辑整段删除，落点也改成「优先选区外，放不下才压在选区内」。

### 控件真的能点

- 工具条 `focusable:true`（仍然 `showInactive`，显示时不抢焦点）；
- 不再「任何命令在跑就禁用所有按钮」，只让正在执行的按钮短暂禁用；
- 按钮加可见底色与描边，取消 / 暂停 / 完成都是 32px 高的实体按钮；
- Esc 取消（全局 + 页内）、空格暂停/继续、回车完成；
- 点「继续」后把焦点还给被截的页面，滚轮和键盘都能直接接着滚。

### 启动不留空档

新顺序：准备工具条窗口并 `loadFile` → 显示工具条 → 收起框选层 → 识别窗口 → 等首帧。
框选层收起时工具条已经在位，中间没有空白画面。

工具条的命中探测点还会避开工具条自身（`sourceProbePoint` 支持多个避让矩形），
避免「窗口几乎占满选区」时把自己识别成采集源。

### 右下角实时预览

新增独立浮窗 `src/long-preview.html`：

- 固定在选区所在屏幕的右下角，24px 外边距，236×302；
- 每拼接一段刷新一次缩略图，底部显示「宽 × 高」和「N 段」；
- 缩略图由 `LongCapture.thumbnail()` 直接按目标像素反查源行生成，不复制整幅位图
  （一张 1200×16000 的长图只需读几万个像素），主进程做了 260ms 节流；
- 同样启用内容保护，并且 `setIgnoreMouseEvents(true)`，不挡滚动、不进长图。

### 更接近微信原生的采集节奏

- 采集间隔 240ms → 150ms；
- 滚动过程中也允许拼接，不再要求画面完全停稳；
- 对不上时**不立即暂停**：画面还在动就继续跟，只有画面停住且连续 5 次仍然对不上，
  才提示「往回滚一点」；状态栏会先给出「正在跟随滚动…」；
- 状态只在真正变化时下发，避免高频 IPC 刷屏。

## 已知边界

内容保护依赖 Windows 10 2004 及以上（`WDA_EXCLUDEFROMCAPTURE`）。
更早的 Windows 会退化成 `WDA_MONITOR`，此时工具条区域在采集里会是纯黑块；
这类系统上工具条仍会优先落在选区之外，减少受影响面积。
