# 浮引 6.0.1：面板显隐、模式切换与键盘事件的函数级分析

版本复核说明：本轮切片与当前安装的 6.0.1（216）重新抽取结果 SHA-256 一致。第一阶段 5.4.0（209）是不同样本；不将本轮函数地址归到旧版本。

分析日期：2026-10-21。对象为本地应用提取的 `fuyin-arm64.macho`，SHA-256：`994fea714090a8a2ee1aaedea5a40ef1789d41f281f87c948eb20502062c1307`。工具为 REA + Ghidra 12.1.4，只读静态分析，没有修改原二进制、授权判断或运行时状态。

本报告共检查 12 个函数，含 3 个 Swift 闭包转发包装。`FUN_...` 是分析器名称，以下中文职责名为分析者根据行为概括，不是恢复的原始函数名。所有地址均为本次 ARM64 分析对象的静态虚拟地址，不能直接用于另一版本或运行时 ASLR 地址。

## 可以直接用于开发方案的结论

1. **面板采用独立状态机管理显隐，不只是切换窗口 visibility。** 函数中存在 `motionState`、`isHidingPanel`、`isMomentaryPanelPresentation`、`currentOpenTarget`、`pendingOpenTarget`、`panelDidOrderNotificationGeneration` 和 `panelOpenTargetPreparationGeneration` 的实际读写。由展示、隐藏分支可以高置信推导 0/1/2/3 分别承担隐藏、展示过渡、稳定可见、隐藏过渡；还存在值 4 的特殊处理，含义未还原。
2. **展示前有内容布局准备和复用判断。** `synchronouslyPreparedOpenTargets`、`preparedPresentationOpenTarget`、`preparedPresentationLayout` 与当前 `presentationState` 比较；必要时才调用 `layoutSubtreeIfNeeded`、`displayIfNeeded` 并更新准备结果。这是减少再次呼出时重复布局的具体证据。
3. **显示、获得键盘焦点、接收内容输入是分开的步骤。** 能观察到 `orderFrontRegardless`、`makeKeyWindow` / `makeKeyAndOrderFront:`，随后 `makeFirstResponder:` 指向 `contentView`。本组证据没有证明隐藏后如何恢复之前应用或控件的焦点。
4. **隐藏时有防重入与事件缓冲。** 隐藏函数增加两类 generation，取消 `displayRepositionTask`，设置 `isHidingPanel`，清除 momentary 标志。可见窗口分支将 `suppressPanelShortcutsUntil` 设置到当前时间之后 0.08 秒，并对 `onShortcutSuppressionRequested` 回调传入 0.1 秒，然后暂时令窗口忽略鼠标事件。
5. **动画可从当前呈现层状态接续。** 动画函数取消之前的 `motionTask`，取 `presentationLayer.transform`（不可得时取 model layer 的 transform），移除已有指定动画，并建立新的 transform 动画。代码中存在 0.16、0.20 和 0.25 秒的时长选择，以及 ease-out / ease-in 的分支；不是测量到的动画耗时。
6. **有自己的展示慢路径记录。** 展示函数读取 `NSProcessInfo.systemUptime`，将两次差值乘以 1000，与 35.0 比较；满足条件时记录 `panel.presentation.slow`，附带 `target`、`momentary`、`prewarmed`、`reusedVisibleWindow` 等字段。这只是记录阈值，不代表面板实测 35 ms、p95 达标或原程序承诺 35 ms。

## 入口与调用链

```text
AppDelegate 路由 0x100086374
  ├─ 无可复用的活动目标 → 0x100a5c4e0 展示
  └─ 活动目标存在 → 0x100a405dc 模式切换 / toggle
        ├─ 0x100a5c4e0 展示
        └─ 0x100a6270c 隐藏

0x100a5c4e0 展示
  ├─ 写 pendingOpenTarget / currentOpenTarget
  ├─ 准备 / 复用布局
  ├─ 0x100a5b588 图层动画
  ├─ orderFrontRegardless / makeKeyWindow
  ├─ 0x100a5dac0 安排主队列回调
  ├─ makeFirstResponder(contentView)
  ├─ addLocalMonitor(mask 0x1400)
  │    └─ 0x100a6e8fc → 0x100a66c68
  └─ 0x100a5dd68 安装内外鼠标监听

0x100a6270c 隐藏
  ├─ generation++ / 标志更新 / 取消重定位任务
  ├─ suppressPanelShortcutsUntil = now + 0.08
  ├─ onShortcutSuppressionRequested(0.1)
  ├─ setIgnoresMouseEvents(true)
  └─ 通常进入 0x100a5b588；另有屏幕边缘返回分支
```

这份链路保留了实际分支的核心含义，但不是源代码逐行转写。特别是 AppDelegate 中几处 helper、模式授权/开关判断及位置判定 helper 的语义仍未确认，不能把它写成完全还原的 `if` 源码。

### `0x100a5c4e0`：准备完成再显示

- 函数要求 `window` 存在。增加 `panelOpenTargetPreparationGeneration`，必要时取 `NSEvent.mouseLocation`。清空 `screenEdgeReturnScreen`，把 `screenEdgeReturnSlot` 置为 `0x10`。
- 如果存在触控板 pinch 展示/关闭状态，清除相应状态，移除 `fuguangTrackpadPinch` 动画，使用 `CATransform3DIdentity` 重置变换。由此能确认不同唤起手势与普通显示共享同一控制器；不能直接推出 Windows 也需要实现相同触控板手势。
- 将目标写入 `pendingOpenTarget`、`currentOpenTarget`。对 `synchronouslyPreparedOpenTargets`、`preparedPresentationOpenTarget`、准备布局与当前布局进行判定。实际 `layoutSubtreeIfNeeded` 调用点为 `0x100a5c994`，`displayIfNeeded` 为 `0x100a5c9b4`。
- 当面板已处于特定稳定状态时，存在复用可见窗口的分支；另一路先处理动画/内容，再将窗口前置。
- 可交叉核对的窗口调用点：
  - `0x100a5cce8` → `makeKeyAndOrderFront:`。
  - `0x100a5ccf0`、`0x100a5d15c` → `orderFrontRegardless`。
  - `0x100a5d16c` → `makeKeyWindow`。
  - `0x100a5cf28`、`0x100a5d3a4` → `makeFirstResponder:`；伪代码中实参来自 `contentView`。
- 如果 `isKeyboardCaptureSuspended` 未置位且 `localKeyMonitor` 尚不存在，调用 `addLocalMonitorForEventsMatchingMask:handler:`，掩码 `0x1400`，调用点 `0x100a5d02c` / `0x100a5d4a4`。该掩码和后续 `type == 0xc` 分支共同支持键按下 / 修饰键变化处理；不据此宣称 Esc、数字键或组合键的具体映射已还原。

### `0x100a405dc`：toggle 根据当前状态选择动作

函数读取 `motionState` 与 `currentOpenTarget`。同一目标在状态 2 时，一部分分支调用 `0x100a6270c(1)`，另一部分调用 `0x100a5c4e0`；目标不同或状态处于过渡时可能重新展示；状态 1 时有直接忽略的分支。

这里还调用 `0x101364118` 进行与窗口及鼠标位置衍生值相关的判断。该 helper 未深入，因此不能把分支条件硬译为“光标是否在面板内”“是否同一显示器”或“屏幕边缘触发”。`currentOpenTarget` 的 0 / 1 也不能仅凭枚举数值命名为剪贴板、启动器等具体业务模块。

### `0x100a6270c`：隐藏是一个可取消、带抑制窗口的流程

可观察到以下顺序：

1. 检查特殊全局状态、motionState 4、pinch 关闭状态和 `isPanelChildWindowTracking`。
2. 非子窗口跟踪分支递增通知及准备 generation，设置 `isHidingPanel = 1`、`isMomentaryPanelPresentation = 0`，取消并清空 `displayRepositionTask`。
3. 若窗口已经不可见，直接清理显隐状态和屏幕边缘返回字段；可见时建立短暂快捷键抑制期。
4. `0x100a629dc`–`0x100a629f8` 构造 0.08 秒间隔并调用 `Date.addingTimeInterval`；`0x100a62a94`–`0x100a62a98` 对抑制回调传入 0.1 秒。它们是两个独立值，不应合并成“统一延迟 100 ms”。
5. 发送通知并在 `0x100a62b48` 令窗口忽略鼠标事件。普通路径进入通用动画函数；另一路基于 `screenEdgeReturnScreen/Slot` 进入屏幕边缘返回函数 `0x100a62d88`，该函数不在本次已展开范围。

子窗口跟踪时不会简单执行整套隐藏；这为“打开系统文件选择器、菜单、子面板时不要误关主面板”的设计提供了具体状态证据。但这组函数尚不足以确认每一种菜单/子窗口的完整判断链。

### `0x100a5b588`：连续动画与显隐状态

该函数先取得 `contentView.layer`，取消 `motionTask`。如果不是从完全隐藏态启动，则优先读取 `presentationLayer.transform`，不可得时才读取 `layer.transform`。随后移除 `fuguangPanelPresentation` 动画，以当前 transform 创建新动画。

关键汇编调用点：`0x100a5b8ac` 取呈现层；`0x100a5bb50` 设置动画 duration；`0x100a5bc38` 添加动画。时长常数 0.16 / 0.20 / 0.25 秒及 ease-in / ease-out 分支直接存在。对应配置 helper 的完整含义没有恢复，不能概括成“所有开关面板动画均为 200 ms”。

状态值判断与实际写入相互印证：

| 值 | 分析者概括 | 直接依据与边界 |
| --- | --- | --- |
| 0 | 隐藏 | 无动画隐藏分支写 0，随后 `0x100a5bf5c` 调用 `orderOut:` |
| 1 | 展示过渡 | 启用动画且展示方向时写 1；数值由 `0x100a5b9b0`–`0x100a5b9bc` 指令选择并写入 |
| 2 | 稳定可见 | 无动画展示分支 `0x100a5bb80`–`0x100a5bb88` 写 2；展示入口也将该状态与 `isVisible` 联合判断 |
| 3 | 隐藏过渡 | 启用动画且隐藏方向时写 3；同一段状态选择指令；完成回调的最终实现尚未展开 |
| 4 | 特殊状态，未命名 | 隐藏入口遇到该值转交 `0x100a5f888`，本次未确认其含义 |

Swift/ARM64 参数恢复有误差，`105-panel-flags.pseudo.c` 显示的函数签名把多个不属于普通 C ABI 的寄存器状态呈现为形式参数。不能按该签名照抄调用。这里的“展示方向 / 隐藏方向”由调用点 `x0` 与本函数保存到 `x24` 后的分支、以及最终窗口操作联合判断，而非仅凭参数名猜测。

### 事件注册与消费

`0x100a5dd68` 只在窗口可见时工作，对 `localOutsideClickMonitor` 和 `globalOutsideClickMonitor` 分别做已存在判断，缺失时才注册。调用点分别为 `0x100a5de94` 与 `0x100a5dff0`，两处 mask 为 `0x200000a`。闭包捕获弱引用，避免仅由监听闭包强持有控制器。

`0x100a66c68` 从弱引用恢复控制器，经过一个未展开的有效性 helper 后读事件类型。`type == 0xc` 与其他类型分两条路径交给 MainActor helper；后一条处理返回真值时，将最终返回事件设为 0，因此存在“处理后消费事件”的行为。这并不证明所有按键都吞掉，也尚未还原具体键位表。

### 延迟任务与完成闭包的范围

`0x100a5dac0` 增加 `panelDidOrderNotificationGeneration`，把控制器弱引用、窗口弱引用与 generation 一起捕获到 main queue 异步工作。`0x100a6ea88` 只是将捕获字段转发给 `0x100a64670`。捕获 generation 支持“存在防过期回调机制”的设计意图推断，但在没有展开最终函数之前，不能声称已验证它确实比较 generation 并丢弃旧任务。

同样，`0x100a6d420` 只是动画完成包装，实际转发到 `0x100a645f0`；本次未展开后者。`0x100a64284` 能确认在布局与准备结果不一致时，向主队列安排另一个弱引用任务；后续任务是否预热、怎样选择布局仍未完全确认。

## 尚未证明的事项

- **来源应用/控件的焦点保存与恢复。** 本组具体函数中没有观察到 `frontmostApplication`、`activateWithOptions:` 或 `previousApplication` 的保存与恢复链。`objc-methods.json` 中 `PanelWindowController` 也未列出 `previousApplication` 字段，但其他控制器存在该字段；元数据字段缺失不能证明程序整体不保存焦点。不能因此把 Windows 原窗口恢复设计写成“从浮引完整还原”。
- **全局快捷键注册与按键组合映射。** 此处只覆盖 AppDelegate 路由、面板局部监听、消费与显隐流程。全局监听如何注册、如何去重以及具体键位尚不在本报告已验证范围。
- **位置 helper 与模式值的具体含义。** 不将地址 helper 强行命名为显示器判断或鼠标命中测试；不把 0/1 开放目标命名为某个模块。
- **所有动画完成路径、屏幕边缘返回路径、触控板手势完整算法。** 已看到接入与状态处理，不等于完整算法还原。
- **实际性能、卡顿原因与线程时序。** 本报告是静态分析。35 ms 日志阈值、动画配置常数、主队列调度和取消调用均不等于运行时测量。

## 对随序 Windows 版的开发落点（独立设计建议）

以下是基于上述行为得到的 Windows 设计建议，不是 macOS 源码移植，也不是对 Windows 版现有实现的描述。

| 模块 | 建议实现 | 验收情景 |
| --- | --- | --- |
| `PanelLifecycle` | 明确 Hidden / Opening / Visible / Closing；所有入口走同一状态机；UI 线程串行提交转换；关闭可中断打开，打开可中断关闭 | 快捷键连续按 20 次后，不残留透明可点击窗口、隐藏窗口不接收面板输入 |
| `PresentationCache` | 缓存控件树与布局；缓存键至少包含目标模式、内容版本、DPI、显示器工作区和主题版本；预热在低优先级进行 | 同一显示器重复呼出与切换 125% / 150% DPI 后尺寸正确，旧缓存不覆盖新布局 |
| `TransitionCoordinator` | 使用 Windows Composition / WinUI 可承载的合成动画；反向操作从当前视觉状态继续；取消令牌与递增 generation 双重控制过期回调 | 动画中立刻关闭或再打开，无闪回、跳变、旧完成回调误隐藏新窗口 |
| `InputRouter` | 区分全局唤起与面板内部按键；可见且面板输入有效时才消费已处理按键；尊重 IME composition；系统菜单、文件选择器、子窗口进入 transient 状态 | 中文输入候选时 Esc 先按约定处理候选，打开文件选择器不会误隐藏主面板，输入不泄漏到来源应用 |
| `DismissalGuard` | 关闭开始立即阻止误点击；短暂快捷键抑制使用单调时钟且可观测；从 80–100 ms 作为候选值开始实测，不强行照搬 | 松开修饰键、按键自动重复、窗口关闭完成前点击背景，不会二次唤起或穿透执行 |
| `FocusReturnService` | 在用户唤起面板前主动保存来源 HWND、进程与可获得的焦点信息；执行动作后先确认用户仍希望回到原窗口，再请求恢复；恢复失败进入明确可理解的退路 | 原窗口关闭、用户主动切换别的应用、管理员窗口、IME 组合输入、多屏时均不会向错误窗口自动粘贴 |
| `PanelTelemetry` | 记录快捷键到首帧、到可输入、到粘贴完成三段时间；区分冷启动、预热、复用及 DPI 改变；日志不含内容正文 | 可复现地输出 Windows 真机 p50 / p95 / p99，而不是把原版日志阈值当性能结论 |

最值得借鉴的是布局复用、状态机、取消与过期任务防护、按需监听和快捷键抑制。Windows 版的焦点恢复应作为自己必须完成的系统能力验证；这部分不能由当前反编译结果替代。

## 还原限制与复核方式

Ghidra 生成的 C 是中间表示。Swift 的隐式 `self`、闭包捕获、异步函数、泛型、Optional、ARC、Combine 发布属性常以 `unaff_x20`、`extraout_*`、`FUN_...` 和间接调用出现。部分中文模块名因工具解码呈乱码，但真实地址、ObjC selector 和字段名仍能帮助交叉核对。日志字符串解码也存在候选误识别：例如动画函数字符串列表中有控制字符候选，本报告仅引用由上下文、常量和调用用途共同支持的字符串。

每个关键判断应以 `.json` 内 `normalized_result.assembly`、`pseudocode`、`callees`、`referenced_names` 及 `limitations` 联合复核。不能只搜索 selector 字符串就称为函数级证据，也不能把主队列捕获或闭包包装误称为全部逻辑已还原。
