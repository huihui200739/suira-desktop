# 随序 SUIRA · Windows 产品与开发方案

版本：提案 v1.1 · 2026-10-21（补充函数级研究，保留雾蓝配色 v2）  
依据：浮引 5.4.0（209）结构/UI 记录及当前 6.0.1（216）函数切片、REA 6.7.0 + Ghidra 12.1.4 函数分析、实际设置界面观察、Microsoft 官方接口资料。

## 1. 产品决策

建议开发「随序 SUIRA」：面向 Windows 的内容处理与交接工具。核心承诺是 **顺手接住，让工作继续。**

用户选中一段文字、框出一张截图，或拖入几个文件，即可处理内容，再回到原来的工作位置。应用、剪贴板、截图、识字和暂存共享同一套内容对象与动作系统。

首批用户选择经常在浏览器、Office、飞书/微信和 PDF 之间搬运资料的知识工作者、产品经理和设计师。第一版围绕三个高频任务设计：

1. 截图 → 提字 → 清理换行 → 放进当前文档。
2. 多次复制 → 按顺序组合 → 一次粘贴，或逐项粘贴。
3. 多处收集图片、链接和文件 → 放进一个任务匣 → 继续处理或导出。

产品是否成立，取决于这些任务是否明显更快、更稳定。工具数量、AI 功能数量和玻璃效果不作为主指标。

## 2. 研究结论与边界

REA 是逆向分析工具，能辅助检查应用、二进制与证据；[项目说明](https://github.com/morluto/rea)并不是浮引的源码。先运行了 REA CLI 的 `inspect-artifact` 和 `inspect-macho`，后通过工作区内 REA/Ghidra 会话执行定向函数反编译，没有修改 Codex 的全局配置。

已经完成：应用包清点、双架构 Mach-O 检查、导入与类型检查、设置界面观察，以及 arm64 主程序中面板、剪贴板、截图和 OCR 的限定核心路径函数分析。尚未完成全应用调用图、完整热键/焦点恢复链、去重落库、模块生命周期状态机、真实交互延迟测量和网络协议分析。下文严格区分静态代码事实、结构推断和 Windows 开发建议；反编译伪代码不是原始 Swift 源码。

### 2.2 实际界面确认的产品行为

- 主面板提供动作面板和应用面板，动作面板采用 38 键排列；支持拼音和首字母搜索。
- 快捷键可配置单键、多键、双击、长按等唤起方式；本机配置包含 Control 和 Option+F。
- 浮引岛已经是文件中转入口，支持拖放、复制/移动策略、拖出保留与 iCloud 相关设置。
- “主动适应”已经可以按应用、时间、系统专注状态组合条件，调整快捷键、入口、屏幕边缘和输入法，离开场景后恢复。
- 截图、长截图、录屏、钉图文、剪贴板、速记、翻译等功能均有明确设置入口。

因此，悬浮球、文件暂存、场景切换、快捷键启动和拼音搜索本身都不能成为随序的核心差异点。对浮引没有逐项测试的能力，不宣称它“不支持”。[官方产品页](https://fg.vkr.me/)可用于补充公开功能范围；本方案的技术结论以本机证据为主。

### 2.3 对“浮引怎么做”的机制解释

结合导入接口、类型名与 UI，可以推断其整体结构为：常驻进程接收唤起事件，窗口控制层呈现对应面板，再调用截图、剪贴板、文件中转等功能服务；各服务由模块运行时管理，历史数据通过本地存储维护，部分内容通过 CloudKit/iCloud 相关组件同步。

上述整体结构仍是综合推断；下节列出的局部机制已有函数体证据。Windows 版本借鉴常驻入口、窗口管理和服务分层，并用 Windows 原生接口独立实现。

### 2.4 函数级研究新增结论

本节函数证据属于当前安装的 **6.0.1（216）**；第 2.1–2.2 节主要保留此前 **5.4.0（209）** 的结构和界面观察。本轮已用哈希确认分析切片身份，未进行两版本完整差异审计。

完整地址、条件分支、Evidence ID、伪代码和限制见 [函数级反编译与 Windows 映射](specs/浮引函数级反编译与Windows映射.md)，详细补充见 [面板追踪](specs/函数追踪-面板.md) 与 [剪贴板追踪](specs/函数追踪-剪贴板.md)。第 2.1 节保留结构层证据，本节补充其函数层结论。

| 子系统 | 已证实的局部机制 | 随序开发落点 |
|---|---|---|
| 面板 | 显隐状态机、准备布局与复用、当前呈现层动画接续；延迟通知实际核对 generation 和窗口状态 | 统一 PanelLifecycle，布局缓存纳入 DPI/主题/内容版本，过期回调不得隐藏新窗口 |
| 输入 | 显示时获取窗口和内容焦点，按需安装键盘及窗口外鼠标监听；隐藏有短暂快捷键抑制 | 区分唤起与面板内输入，处理 IME、子窗口和关闭期间误点击；来源焦点恢复仍需独立完成 |
| 剪贴板 | 一条后台路径配置 1.3 秒 timer、250 ms leeway；变化检查、代次递增、取消旧任务、读前后核对和有界重试 | Windows 继续采用系统变化通知，叠加内容版本和取消令牌；不照搬 macOS 后台周期 |
| 截图 | SCScreenshotManager 实际调用，回调入口用锁和完成标志避免重复 resume | 采集成功/失败/超时/取消统一竞争一次完成出口，丢弃迟到结果 |
| OCR | Vision 实际请求、topCandidates(1)、trim、矩形与置信度、换行拼接；缓存复用与取消检查 | 保存结构化文字块，缓存包含引擎及参数版本，整理文字生成新结果 |

1.3 秒是某条后台监控配置，35 ms 是面板慢路径日志阈值，都不是原产品的实测响应速度。去重、隐私过滤、最终数据库事务和模块资源释放效果仍不能下结论。这些缺口不阻止 Windows 样机开发，须按自己的需求和验收矩阵完成。

## 3. 品牌、名字和图标

**主推名称：随序 · SUIRA**  
**产品描述：你的 Windows 随手工作台**  
**品牌短句：顺手接住，让工作继续。**

“随”对应随手可用、跟随当前任务；“序”对应收集和处理后的秩序。名称既能承载截图、剪贴，也能扩展到工作流。SUIRA 作为英文识别名，不赋予虚构词源。当前属于创意工作名；正式发行前单独完成商标、域名和商店同名核验，初步网页搜索不能替代这些检查。

备选中文名：“轻渡”（强调内容交接）、“即序”（强调快速整理）。主方案统一使用随序，避免多品牌并行。

### 视觉方向

- 主色：冷石墨 `#252B35`；浅色背景：银白 `#F4F6FA`；正文：蓝灰 `#263040`。
- 强调色：雾蓝 `#506F9E`；冰蓝 `#B7CBEA` 用于标识和轻量高亮。按钮、选中态、焦点与深浅色模式统一使用蓝灰色系，去除原先的绿色底色倾向。
- 图标：两段瓷白与冰蓝的柔角曲带，构成连续的 S 形通道；表达接住、转接和继续。独立于浮引现有的 F 形、蓝紫羽翼视觉。
- 当前图标概念资产：`brand/suira-icon-ice-blue-v2.png`，透明外背景，冷石墨底板，克制的陶瓷层次。属于原创栅格概念稿；旧版青绿图标只作历史稿保留。
- 发布前绘制同轮廓的矢量母版和单色托盘版，分别校正 16/20/24/32px 的光学尺寸；不要把大图直接缩小当作所有尺寸成品。
- 界面使用 Segoe UI Variable / 系统中文字体，14px 正文，12px 辅助信息，8px 间距体系，常规控件 8px 圆角，主面板 16px 圆角。
- Acrylic 只在短暂浮层中少量使用；正文、截图、编辑区保持清晰。关闭系统透明效果时切换实色。深浅色都作为正式设计交付。

高级感来自信息克制、对齐、字重和稳定反馈。不要靠大面积模糊、持续发光和弹跳动画制造质感。

## 4. 差异化产品结构

| 方向 | 浮引已观察到的能力 | 随序的设计选择 | 验证方式 |
|---|---|---|---|
| 主入口 | 38 键固定动作面板、应用面板 | 一个紧凑搜索/动作面板；先展示当前内容与 3–4 个相关动作，固定收藏保持位置 | 首次使用者能在 1 分钟内完成一条任务 |
| 工具组合 | 多种工具、面板和情境配置 | 用同一个内容对象串联动作；每一步保留输入、输出和来源 | 截图提字清理粘贴无需反复开窗口 |
| 暂存 | 文件浮引岛，剪贴板历史 | “任务匣”组合文本、图片、文件和链接，并保留派生关系、处理进度 | 暂停后能恢复同一任务的中间结果 |
| 返回工作 | 存在辅助功能和事件接口，具体路径未完整验证 | 把目标窗口验证、焦点返回、粘贴回退做成独立子系统 | 不向用户已经切换的新窗口误贴 |
| Windows 整合 | 当前观察对象为 macOS 应用 | 原生多屏/DPI、Explorer 新右键菜单、标准拖放与包身份 | 在实际 Windows 应用矩阵中验收 |
| 稳定手感 | 本次没有测量 | 明确响应预算、排序冻结、取消和重试语义 | 采集 P50/P95、超时率和误操作率 |

这些是产品重点与交互结构的区别，不宣称行业首创。后续竞争比较应把 Windows 剪贴板历史、PowerToys Run、截图工具等纳入用户测试基线，而不是用功能数量比较。

## 5. 三个核心界面

### 5.1 随手面板

建议初始快捷键 `Ctrl+Alt+Space`，安装时检查注册冲突并允许改键。避开默认占用 `Alt+Space`、`Win+V`、`Win+Shift+S`，保留用户已有习惯；国际键盘需要验证 AltGr 兼容性。

面板宽约 620 DIP，默认不超过 7 行。顶部为搜索框；下面显示当前选区、剪贴板或截图的小型来源预览；中间是相关动作；底部显示 Enter、Tab、Esc 等可用操作。

- 无内容时：搜索应用、命令、收藏；应用搜索首期扫描开始菜单快捷方式及已注册应用，不做全盘文件索引。
- 有文字时：清理格式、合并换行、加入任务匣；翻译在联网能力可用后出现。
- 有图片时：提取文字、钉住、标注、加入任务匣。
- 有文件时：加入任务匣、复制路径；压缩和改名在后续版本加入。
- 输入法处于组合输入时不执行字母快捷动作。键盘路径使用 Enter/Tab/方向键；用户明确切换动作模式后才解释短键。
- 面板打开后冻结候选顺序，异步结果只补充到指定区域，避免鼠标将要点击时项目换位。

搜索模式接收焦点；预览、提示和任务匣迎接条尽量不激活窗口。用两种窗口状态解决不同需要，不能对所有浮窗统一设置“永不抢焦点”。

### 5.2 任务匣

任务匣是一个可折叠侧边面板，用户显式打开或拖入时出现；不常驻桌面中央。默认任务为“临时收集”，也能建立“竞品研究”“本周周报”等命名任务。

同一任务可以包含选区文字、截图、链接、文件引用及其处理结果。例如，一张截图旁边能看到由它识别出的文字、清理后的文字，以及待粘贴状态。文件默认记录引用，拖出默认复制；只有用户显式选择移动时才移动原文件。

“继续这个任务”恢复任务内的内容与中间结果；恢复外部文档的精确光标位置只在适配器支持并校验有效时提供。首期不承诺重启后恢复任意第三方软件的内部光标。

### 5.3 处理轨迹

处理轨迹以短横向步骤呈现，例如“截图 → 提字 → 合并换行 → 粘贴”。它只在多步骤任务中出现，不把普通复制变成复杂编辑器。

- 生成内容以新版本保存，不覆盖原始捕获。
- 本地转换可回退；失败后停在当前步骤，可更换动作并继续。
- 粘贴、写文件等副作用只在最终提交时发生，不在预览时执行。
- 取消后丢弃过期异步结果；已发生的外部操作必须明确标记，不能显示成“已全部撤销”。

## 6. MVP 与迭代顺序

### P0：首发必须完整跑通

| 能力 | 首期边界 | 验收重点 |
|---|---|---|
| 快捷面板与搜索 | 命令、应用、收藏、拼音/首字母 | 冲突提示、中文输入法、开关面板稳定 |
| 剪贴板历史 | 文本/图片/文件引用，搜索、收藏、排除来源、保留期 | 去重、重启恢复、超大内容、占用锁重试 |
| 区域截图与标注 | 单屏区域、跨屏区域、箭头/文字/遮盖、复制/保存 | DPI 坐标、HDR/SDR、取消、导出 |
| 钉图文 | 置顶、缩放、透明度、临时收起 | 不干扰输入、显示器变化后可找回 |
| 离线 OCR 与文本清理 | 中英文；合并换行、去多余空格、纯文本 | 识别可编辑，失败可重试 |
| 任务匣 | 混合内容、来源、派生关系、批量复制/导出 | 引用失效、恢复、磁盘配额 |
| 动作链与放回 | 内置 3 条模板；显式执行 | 目标窗口校验、取消、粘贴回退 |
| 基础设置与发布 | 快捷键、外观、数据、排除规则、更新 | 安装/卸载、数据库迁移和更新失败恢复 |

### P1：首发稳定后

模板编辑器、顺序粘贴队列、图片批处理、Explorer 新右键入口、按应用的常用动作配置、用户自带模型 API 的翻译/润色。AI 只作为已有动作系统的可选执行器；本地基础任务在离线状态仍可完成。

### P2：验证需求后

限定应用的长截图、录屏、浏览器适配器、脚本扩展、可选择的加密同步。首发不同时建设完整 Markdown 编辑器、日历、手机遥控、插件商店和账号云平台。

长截图需要单独攻克固定页眉、重复区域、滚动容器与虚拟列表；不能仅靠周期性滚轮和拼图就宣称通用支持。

## 7. Windows 技术方案

### 推荐组合

**C# + WinUI 3 / Windows App SDK Stable + Win32 互操作；图像与窗口底层按需要使用 C++/WinRT。** 首期面向 Windows 11，具体最低受支持版本在技术预研周结合生命周期与测试设备冻结；先交付 x64，随后完成 ARM64 原生验收。

这是基于深度系统交互和 Windows 体验作出的工程建议。Microsoft 将 Windows App SDK 定位为新 Windows 桌面应用的推荐平台，并支持 WinUI、窗口管理和部署等能力。[官方平台说明](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/)

| 选项 | 适用条件 | 本项目决策 |
|---|---|---|
| WinUI 3 + Win32 | Windows 优先、系统整合深、需要 Fluent 原生组件 | 主方案；先验证浮窗、托盘、焦点与截图的难点 |
| WPF + Win32 | 团队已有深厚 WPF 经验，优先降低学习成本 | 可行备用；用同样的窗口与性能指标验证 |
| Tauri / Electron | 团队以 Web 为主或跨平台为主要目标 | 本期不选；跨平台收益不足以抵消系统适配成本 |

不要同时维护两套完整 UI 栈。第 1 周做可运行技术样机，实测决定主方案是否通过门槛。

### 进程与模块

```text
Suira.Host                 常驻、托盘、热键、轻量面板、焦点与生命周期
  ├─ ContextBroker         选区/剪贴板/拖放上下文，超时与来源校验
  ├─ ActionRegistry        类型匹配、固定收藏、候选顺序、执行计划
  ├─ ClipboardService      WM_CLIPBOARDUPDATE、序号、去重、排除规则
  ├─ CaptureService        图形采集、区域坐标、钉图窗口
  ├─ TaskStore             SQLite 元数据、加密内容、迁移和容量管理
  └─ ReturnTargetService   目标 HWND/PID/启动时间、焦点与粘贴提交

Suira.Worker               按需启动的 OCR/图像/重处理；有界队列和取消
Suira.ContextWorker        可被终止重启的 UIA 查询，防第三方控件卡住
Suira.ShellExtension.dll    P1 原生 Explorer COM 扩展，只转发轻量命令
```

Host 与 Worker 通过当前用户权限限制的命名管道通信。消息包含协议版本、jobId、输入引用、取消标识和截止时间；大图通过受控临时文件/共享资源传递，不在 JSON 中反复 Base64。进程拆分按故障隔离和实测内存决定，常驻状态不保留空闲重处理进程。

### 能力到接口的对应

| 能力 | Windows 实现路径 | 要处理的边界 |
|---|---|---|
| 热键 | `RegisterHotKey` + 消息循环 | 冲突检测；默认不全局接管 Control/Shift 单键 |
| 托盘/浮窗 | `Shell_NotifyIcon`、HWND、AppWindow、必要的窗口扩展样式 | 搜索窗口与不激活预览分开；禁止长期误置顶 |
| 选区读取 | UI Automation TextPattern/GetSelection；不可用时让用户复制或框选 OCR | UIA 不等于任意软件都可读；查询必须有截止时间 |
| 剪贴板 | `AddClipboardFormatListener` / `WM_CLIPBOARDUPDATE` | 延迟呈现、锁竞争、自写回环和格式兼容 |
| 屏幕采集 | Windows.Graphics.Capture + D3D11；自定义区域遮罩裁剪 | 多屏负坐标、设备丢失、HDR、受保护画面 |
| 图像/标注 | Win2D 或 Direct2D；WIC 导出 | 保存原图和标注模型；导出时栅格化遮盖 |
| OCR | 首期评估 Windows.Media.Ocr；缺语言/精度不足时提供经验证的本地引擎 | 引擎按能力探测；不能要求所有 PC 有 NPU |
| 拖放 | OLE `IDataObject`、`CF_HDROP`；后续扩展虚拟文件格式 | 不保证所有软件接受相同格式；可回退保存文件 |
| 粘贴 | 校验目标、请求焦点、写剪贴板、必要时 `SendInput` | UIPI、窗口关闭、输入法组合和焦点变化 |
| Explorer 菜单 | 原生 `IExplorerCommand` + 包身份 | 菜单构建路径不执行 OCR、压缩等重任务 |
| 持久化 | SQLite WAL + DPAPI 加密内容与数据密钥；版本化迁移 | WAL、临时图、索引与崩溃日志也不能遗留正文 |

剪贴板监听用系统事件，无需高频轮询。[监听 API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener)。UIA TextPattern 主要用于读取；它不是通用写入机制。[TextPattern 说明](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-textpattern-overview)

图形采集通过系统 API 获取显示器/窗口内容，再在应用中框选裁剪；WinUI 桌面使用系统选择器时需要初始化 HWND。[采集说明](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/screen-capture)、[CreateForMonitor](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createformonitor)

新的 Windows AI OCR 仍有硬件要求，适合作为可选增强，不作为普通 Windows PC 的首发依赖。[OCR 官方说明](https://learn.microsoft.com/windows/ai/apis/text-recognition)

Explorer 新右键菜单需要 `IExplorerCommand` 和应用身份；未打包应用也可以通过 sparse package 获得身份。采用原生小 DLL，避免把整套业务运行时加载进 Explorer。[菜单扩展说明](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)

### “放回原处”的实现约束

唤起前记录目标 HWND、PID、进程启动时间、选区获取方式和输入法状态。进入面板后不随每次前台变化覆盖原目标；提交前再次检查原目标仍存在且属于同一进程实例。用户明确切换了目标、原窗口关闭或权限不匹配时，显示“已复制，切回目标后粘贴”。

`SendInput` 受 UIPI 限制，普通权限程序不能可靠向更高完整性级别窗口注入输入；不默认让整个产品以管理员身份常驻。[SendInput 限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

写入剪贴板时记录序号并标记自身来源，防止历史回环。仅在已确认本次写入仍未被用户新复制覆盖时考虑恢复旧内容；无法确认目标已消费内容时保持结果可用，不用固定几十毫秒的定时器抢回剪贴板。支持明确选择“仅复制”和“返回并粘贴”。

### 函数研究转化为实现约束

- 面板转换由 UI 调度器串行提交，使用 Hidden / Opening / Visible / Closing。动画可反向接续；延迟通知核对 generation、当前窗口和可见状态。布局缓存随 DPI、显示器工作区、主题或内容版本变化失效。
- 剪贴板每次变化递增 capture generation；读前、读后、重试前与提交前检查版本。取消旧任务后仍防迟到结果。多格式优先级、去重、敏感内容排除和事务由随序独立定义；保存原文，trim 或清理作为派生动作。
- 截图任务用 jobId 和一次完成出口处理成功、失败、超时与取消；清理资源后不能被迟到回调重新激活。OCR 缓存按图像哈希、引擎版本和识别参数区分；输出文字块及可用的矩形/置信度，再生成全文。
- 第 1 周样机验证快速开关和动画中断；第 3–4 周验证连续复制、读期间再次复制和锁竞争；第 5–6 周验证取消后的迟到结果、重复识别和缓存失效。这些任务并入原排期，不将研究样本的配置常数当作 Windows 性能结论。

## 8. 动作系统与数据结构

所有工具遵循统一协议，避免每加一个功能就增加一套入口和数据模型。

```text
ContentItem = id + kind + payloadRef + source + createdAt + parentIds
Source      = appId + windowIdentity? + acquisitionMethod + confidence
Action      = stableId + acceptedTypes + outputType + executor + sideEffect
Execution   = jobId + inputIds + actionId + status + outputIds + error
Task        = id + title + itemIds + recipeId? + progress + retentionPolicy
```

`kind` 首期限定 text、image、files、link、collection。来源有确定/推测/未知状态：剪贴板前台窗口不一定是内容真正来源；网页 URL 只有显式复制、用户输入或后续授权浏览器适配器获得时才记录，不能把窗口标题猜成 URL。

内置配方示例：

```json
{
  "id": "capture-to-clean-text",
  "version": 1,
  "accepts": ["image"],
  "steps": [
    {"action": "ocr.local", "onError": "stop"},
    {"action": "text.merge-lines", "onError": "stop"},
    {"action": "output.preview", "onError": "stop"}
  ],
  "commit": {"action": "output.copy-or-paste", "explicit": true}
}
```

重处理与副作用分离：OCR/格式转换可按输入哈希复用结果，写文件/粘贴不能因网络重试或 Worker 重启而自动重复。提交记录需要幂等标识；不确定外部是否完成时让用户确认当前状态，再决定重试。

### 存储与搜索

- SQLite 保存元数据、任务关系、动作执行与迁移版本；图片与富文本内容按引用保存。
- 内容使用当前用户保护的密钥加密。首期可对有限历史做解密后的内存搜索，以实际容量测试为准；不把敏感正文另写入明文 FTS5 索引。
- 若后续需要大容量全文搜索，统一评估加密数据库与索引方案，不能声称“正文加密”就等于所有派生数据已加密。
- 默认保留最近 30 天/2,000 条，设置总容量上限；收藏单列预算。用户可暂停记录和按应用排除。
- 密码管理器等来源默认排除；标准敏感标记能识别时尊重它，但不能承诺自动识别所有密码和密钥。提示用户可一键暂停历史。
- 缩略图、转换临时文件有清理期限；崩溃记录默认不包含正文、完整文件路径或画面。

## 9. 把“丝滑”变成验收指标

**下列是开发目标，不是浮引或随序的已测成绩。**

统一基线：Windows 11 真机、四核级 CPU、16GB RAM、SSD、集显；明确显示器和电源模式。对 100% / 150% / 200% DPI、60Hz / 120Hz 分组记录。至少连续采样 200 次热唤起，报告 P50、P95、最差值和失败率。

| 项目 | 初始目标 | 计时/测量口径 |
|---|---|---|
| 热唤起 | P95 ≤ 100ms | 收到热键 → 首个可交互帧；不把动画结束当作开始 |
| 首次启动后可唤起 | ≤ 2s 的研究目标 | 进程启动 → 热键注册且面板可操作；单独报告冷启动 |
| 搜索反馈 | P95 ≤ 50ms | 输入提交 → 当前缓存候选更新；不含外部网络 |
| 区域截图反馈 | P95 ≤ 150ms | 鼠标释放 → 可见预览；OCR 另计 |
| 常规 OCR | 1080p 中英文样例 P95 ≤ 1s 的预研目标 | 请求 → 可编辑文字；注明引擎、语言和模型预热 |
| 动画 | 60Hz 下 16.7ms 帧预算；120Hz 下 8.3ms | ETW/PresentMon 采样并观察掉帧，禁用持续背景动画 |
| 动画时长 | 打开 140ms、关闭 100ms，允许被新输入打断 | 首帧即可接收操作；遵循系统减少动画偏好 |
| 常驻资源 | Host 空闲私有工作集以 ≤ 100MB 为预研目标；空闲 CPU 接近 0 | 不含活动 OCR/录屏；UI/Worker 峰值与恢复分开报告 |
| 可靠性 | 指定测试矩阵中 1,000 次开关与放回无误贴、无卡死 | 焦点变化、超时和拒绝执行作为独立结果统计 |

实现措施：面板预创建但释放隐藏大图；动作元数据、常用图标和应用索引缓存；数据库、缩略图、OCR 和 UIA 查询移出 UI 线程；UI 更新合并；有界并发；取消令牌；多屏坐标统一；模块闲置后卸载。

不能靠 `SetProcessWorkingSetSize` 强制清空工作集来“达标”，也不能把所有内容都预热进内存。测量使用 Windows Performance Recorder/Analyzer 和 .NET 性能工具，具体选型在 POC 冻结。

## 10. 开发排期与交付门槛

估算前提：2 名熟悉 Windows 的工程师，约 0.5 名产品/设计与 0.5 名 QA；不含账号云同步、通用长截图、完整录屏编辑。**首发预计 12–16 周，按 14 周规划。** 单人需要约 5–7 个月，实际工期由第 1 周技术风险与团队经验校正。这是规划估算，不是固定报价。

| 周期 | 交付物 | 必须通过的门槛 |
|---|---|---|
| 第 1 周 | WinUI/Win32 技术样机；热键、托盘、选区、截图、返回目标 | 多 DPI 可用；焦点失败可控；初步内存/热唤起测量 |
| 第 2 周 | 设计系统、原生面板骨架、动作协议、数据模型 | 输入法与键盘完整路径；明确功能边界 |
| 第 3–4 周 | 剪贴板历史、存储、搜索、保留期、排除规则 | 重启恢复、锁竞争、自写回环、迁移测试 |
| 第 5–6 周 | 区域截图、标注、钉图、离线 OCR | 混合 DPI、取消、图像导出与语言包回退 |
| 第 7–8 周 | 任务匣、内容派生、3 条内置动作链、放回子系统 | 三条端到端任务都可用；失败可继续处理 |
| 第 9–10 周 | 交互打磨、性能、资源释放、安装更新 | 指标有实测报告，连续运行无持续内存增长 |
| 第 11–12 周 | 20–30 人封闭测试、兼容修复、帮助引导 | 收集真实失败路径和任务完成时间；严重缺陷清零 |
| 第 13–14 周 | 发布候选、签名打包、回滚演练、支持材料 | 干净系统安装；升级/卸载；数据兼容验证 |

第 1 周如果热键/浮窗/捕获等关键问题未通过，不进入大规模功能开发。第 8 周可发布内部 Alpha，第 12 周是否扩大测试由质量决定。ARM64 与 Explorer 扩展按独立门槛加入，不能只做交叉编译就宣布支持。

### 建议首周工程任务

1. 建立 Windows 真机和 CI 构建，锁定 SDK/NuGet 版本、目标架构与安装模型。
2. 做热键 → 面板 → Esc 返回循环，验证 IME、DPI、多屏及重复按键。
3. 做浏览器/Word/记事本/飞书的选区读取与目标返回能力表。
4. 做屏幕采集与裁剪最小实现，验证 HDR 和负坐标。
5. 做事件式剪贴板监听及自身写入去重。
6. 对上述样机做首次性能采样，按事实调整预算。

## 11. 质量与风险清单

| 风险 | 实现与测试方法 |
|---|---|
| 焦点跳错、误贴 | 校验 HWND/PID/进程实例；切换窗口、关闭文档、管理员目标分别测试；失败保持可复制结果 |
| 中文输入法误触 | 组合输入期间禁用动作短键；微软拼音、搜狗等真机测试；支持纯搜索模式 |
| 多屏错位 | Per-Monitor DPI Awareness V2；100/150/200% 混合、负坐标、拔插屏、睡眠恢复 |
| UIA 查询卡住 | 独立工作进程、截止时间、取消与重建；不得让 UI 主线程等待第三方控件 |
| 采集黑屏或颜色异常 | 检测受保护内容、GPU 设备变化、HDR/SDR；保留可理解的错误与替代路径 |
| 截图遮盖泄露 | 导出时真正覆盖像素；不把原始画面作为附加层夹带到分享文件 |
| 历史内容泄露 | 排除规则、保留期、加密正文与派生缓存、日志脱敏；搜索方案不落明文副本 |
| 文件引用失效 | 展示失效状态；允许重新定位；批量操作预览冲突；不静默覆盖同名文件 |
| 更新损坏数据 | 迁移前一致性快照；可回退安装；每次升级验证数据版本兼容 |

应用兼容矩阵至少覆盖 Edge/Chrome、Word/Excel、Windows 记事本、VS Code、微信、飞书、一个主流 PDF 阅读器。每个软件分别验证“可读选区”“可粘贴文本/图片/文件”“权限受限时的回退”，不使用单一“已支持”勾选。

自动化测试集中在有价值的边界：动作类型匹配、取消与幂等、坐标换算、迁移恢复、剪贴板回环。焦点、输入法和图形体验仍需要真实 Windows 桌面与人工检查；网页概念稿不能替代这些验收。

## 12. 安装、更新与商业化

首期优先验证带包身份的签名 MSIX 分发；官网旁加载需要可信签名与清晰的安装引导。Store 与独立安装渠道分别验证自启动、更新和卸载行为。离线部署需求明确后再评估 signed EXE + sparse package，不为首发并行维护过多安装路径。

产品不强制登录，基础数据保存在本机。建议基础截图、OCR、剪贴板与钉图可完整体验；付费重点放在高级配方、批处理和任务管理。使用“本地功能买断 + 后续大版本可选升级”作为待验证的商业方向，云服务另算成本；价格在封闭测试后研究，当前不把未经验证的价格写成定价结论。

评估产品价值的实验：让测试者用现有工具和随序分别完成三个相同任务，观察任务时长、切换次数、第一次成功率和一周后再次使用情况。以任务时长中位数减少 30% 作为试验目标，达不到时优先修正流程。
