# 随序 · SUIRA

> 你的 Windows 随手工作台。**顺手接住，让工作继续。**

Electron 实现的 Windows 桌面端样机。产品方向、交互结构与验收标准来自 `Suira-Windows-Docs/`，
本仓库是据此开发的**可运行实现**，不是概念稿。

当前进度：第一批（38 键动作面板 / 应用面板 / 工具箱 / 设置）与第二批（键位接入真实能力）
已完成；第三批按 `docs/BATCH3-GAP-ANALYSIS.md` 的顺序开工，**已交付前四项**——
自定义唤起增量（按住型唤起、面板布局轮换、钉图显隐）、浮引岛（文件中转）MVP、
图片取词翻译（翻译 B 支）与**速记（纯文本，可钉桌面）**。

2026-10-24 增量：**区域录屏**（面板 S / 工具箱 / 搜索入口，支持倒计时、暂停/继续、系统声音与 WebM 保存）和**钉图右键菜单**已接通。剪贴板、截图工具栏、速记和钉图与悬浮面板共用明暗主题材质。见[本轮实现与验证](docs/UNIFIED-SURFACES-AND-RECORDING-2026-10-24.md)及[界面预览](docs/preview/unified-ui-2026-10-24/overview.png)。

## 快速开始

```powershell
npm install
npm start          # 启动应用
npm test           # 核心逻辑、渲染与交互回归
npm run test:panel # 面板布局、异步竞态与错误反馈回归
npm run diag       # 启动自检，生成环境报告
npm run clean      # 清理闲置测试缓存与临时测试包，保留正式数据
```

> 打包：`npm run dist`（NSIS 安装包）或 `npm run dist:portable`（免安装单文件）。

> 启动遇到问题？先看 [docs/KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md)。

`clean` 会校验删除范围并跳过仍在使用的目录；不会删除 `node_modules`、正式用户数据或当前运行的 Electron。旧的本机专用启动探针已移除，验证脚本统一使用当前运行环境。

> **要在真机上验证？** 照着 [docs/REAL-MACHINE-CHECKLIST.md](docs/REAL-MACHINE-CHECKLIST.md)
> 走一遍，34 项逐条列出预期结果。先跑 `npm run diag` 能省掉大半排查时间。

## 三个核心流程

主入口为 38 键动作面板（`Ctrl+Alt+Space` 唤起）后的链路：

### 1. 截图 → 提字 → 清理换行 → 放进文档

`Ctrl+Alt+A` 唤起截图覆盖层 → 框选区域 → 工具栏点「提取文字」→ 离线 OCR 识别 →
结果面板可直接编辑 → 「加入任务匣」或「复制」。

识别结果作为**派生内容**保存，原始截图不被修改。

### 2. 多次复制 → 按顺序组合 → 一次粘贴

剪贴板历史自动记录文本、图片、文件引用与链接。在任务匣中按需要的顺序收集，
再整体复制或导出为 Markdown。

### 3. 多处收集 → 任务匣 → 处理或导出

任务匣把混合类型内容放在同一个任务里，并保留**派生关系**：
一张截图旁边能看到由它识别出的文字、整理后的文字。顶部的处理轨迹条显示
`接住内容 → 提取文字 → 合并换行 → 复制` 的当前进度。

### 4. 顺手暂存 → 浮引岛 → 拖回任何地方

把文件从资源管理器拖到屏幕顶部居中的浮引岛 → 岛展开成卡片；需要用时把卡片直接拖回
资源管理器或应用窗口。文件本体不复制，只记引用，重启后仍在。拖入策略（复制 / 移动）
可切换；这是原产品「文件中转」的 Windows 落点，不替代任务匣。

## 快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl+Alt+Space` | 打开 / 收起 38 键动作面板 |
| `Ctrl+Shift+A` | 区域截图 |
| `Ctrl+Alt+Q` | 面板布局轮换：动作 → 应用 → 工具箱 |
| `Ctrl+Alt+H` | 钉图显隐：有可见钉图时全部隐藏，再按一次恢复 |
| `Ctrl+Alt+V` | 底部剪贴板历史条：← → 选择，Enter 复制并尝试粘回原窗口 |
| `Ctrl+Alt+Shift+Space` | 按住型唤起：按住显示面板，松手立刻收起 |
| `Esc` | 关闭面板 / 取消截图 / 关闭剪贴板历史条 |

> 截图覆盖层现在是**预热常驻窗口**：第一次唤起后，之后每次截图只做 show/hide，
> 不再新建窗口和加载页面；拖动选区时的 pointermove 按屏幕帧合并、工具栏只在
> **松开鼠标框选完成后**出现，全程不做强制布局读取。

> `Alt+F` 作为历史兼容键也绑定了面板。以上键位都可在设置页改键、清除绑定、恢复默认；
> 相机/截图类全局键冲突会给出原因并自动回滚。

面板内：`空格` 在动作面板 / 应用面板之间切换，`字母键` 直达对应动作，
`/` 或 `F3` 聚焦搜索，`↑` `↓` `Enter` 选择搜索结果，`Esc` 逐级返回。

> 热键通过 `ShortcutManager` 注册，**有冲突检测**：注册失败会在设置页显示原因并支持改键，
> 改键失败自动回滚到原键位。设置页还支持**恢复默认**（一键回到出厂键位）和
> **清除绑定**（解绑后不再响应，条目保留可重新绑定）——对应原产品
> `KeyboardShortcutRecorderController` 的 `restoreDefault` / `clearShortcut`。
> 清除结果会落盘：重启后仍是「未绑定」，不会被默认值悄悄顶回来。

### 按住型唤起（第三批增量）

原产品把唤起分成两套语义：切换型（按一下开、再按一下收）和**按住型**（按住显示、松手收起）。
Electron 的 `globalShortcut` 只在按下时回调，拿不到「松开」，因此这里用一条旁路：

- `assets/key-watch.ps1`：常驻 PowerShell 助手，用 `GetAsyncKeyState` 按 25ms 轮询指定 VK 组合，
  输出 `READY` / `DOWN` / `UP` 边沿与 `ERROR`；父进程 stdin 关闭即自行退出。
- `lib/key-watch.js`：`KeyWatchProbe` 状态机（`idle → starting → watching → stopped`），
  按行缓冲解析、边沿去重、READY 5 秒超时、退出兜底，纯 Node 可测。
- 主进程接线：`onDown` 显示面板、`onUp` 收起；按住期间若助手异常退出会先补一次 `onUp`，
  面板不会卡在显示态。设置页显示「按住生效，松手收起」或具体失败原因。

## 核心框架（本轮补齐）

按「先把截图 / 剪贴板 / 主体做完整，再加新功能」的顺序，本轮把三大基础框架的缺口
逐项补齐，并用**真实 Electron** 跑通端到端链路（`npm run verify:core`，61 项）。

| 框架 | 之前的状态 | 本轮补齐 |
|---|---|---|
| 截图 | 截图→标注→复制/钉图/OCR 代码齐全，但 **OCR 在 Electron 主进程会永久卡住** | 修正 tesseract.js 的环境误判（见下）；保存对话框不再以隐藏主窗口为父窗口；真机验证 复制 / 钉图 / 提字 全链路 |
| 剪贴板 | 只采文本与图片；来源应用字段是空；同一内容复制两次会存两条 | 采集**文件引用**（`text/uri-list` → 多路径），记录**来源应用/窗口标题**（敏感应用排除真正生效），重复内容**置顶不新增**，启动与修改保留期时即时清理 |
| 主体 | 四个页面可用，但缺预览、粘贴回原窗口、失败重试、窗口记忆 | 内容库**预览层**（图/文/文件）、**粘贴回原窗口**（复用放回子系统，失败降级为「已复制」）、轨迹**失败重试**、**窗口位置/尺寸/最大化记忆**（多屏校验后恢复） |

### 本轮体验优化（截图手感 / 工具栏时序 / 底部剪贴板条）

- **截图流畅度**：覆盖层窗口改为**启动时预创建、之后只 show/hide**（不再每次新建
  `BrowserWindow` + `loadFile`）；两个 canvas 去掉 `willReadFrequently`（不再强制软件渲染）；
  `pointermove` 用 `requestAnimationFrame` 合帧；拖动期不再每帧读
  `getBoundingClientRect` / `offsetWidth`（会强制同步布局），工具栏尺寸改为惰性测量缓存；
  选区外压暗从 `100vmax` 的 box-shadow（等于每帧整屏重绘）改成 **4 块矩形条带**。
- **工具栏时序**：拖动框选时只显示橡皮筋与顶部提示，**松开鼠标形成有效选区后**才出现
  编辑工具栏；在已有选区上移动/缩放时工具栏保持可见并跟随；重新框选时先收起。
- **底部剪贴板历史条**：`Ctrl+Alt+V` 在屏幕底部弹出横向历史带（最大 1600×310，贴工作区底部
  16px）；图片显示缩略图、文字显示摘要、文件显示文件名；← → / Home / End 选择，
  滚轮或触控板横向滑动，Enter **复制并尝试粘回打开前的应用**（回不去时提示「已复制」），
  Esc 或失焦收起。图片条目复制的是**位图**，不是文件路径文本。

---

### OCR 在 Electron 主进程里卡死的修复（重要）

`tesseract.js` 用 `is-electron` 判断运行环境：在 Electron 主进程里 `env` 是 `electron`
而不是 `node`，它会把本地 `langPath` 当成 URL 去 `fetch`，抛出
`TypeError: Only absolute URLs are supported`，而 `createWorker` 永远等不到就绪消息——
用户看到的现象是「截图提字一直转圈」，且没有任何报错。修法不改 `node_modules`：
`OcrService.prepareLanguageCache()` 先把随应用附带的 `.traineddata.gz` 解压进
`cachePath`，缓存命中后 tesseract 不再走 fetch 分支。`test-ocr.js` 锁住这个行为，
`verify:core` 在真实 Electron 里用带文字的图片验证识别结果。

  **未配置时明确提示去设置，不产出假译文**。密钥用数据密钥加密后落盘，
  渲染层只能看到「是否已保存」；三家引擎的请求构造、回包解析、错误说明都有离线单测
- **速记（第三批第 4 项，纯文本）**：`N` 键 / 工具箱 / 托盘三个入口，接着最近一条写，
  没有才新建——每次都新建会留下一堆空笔记。一条笔记一个窗口，可**钉在桌面**（置顶），
  **位置随笔记记住**（拔掉副屏后回落到可见位置）。标题由正文第一行推导，不另设输入框。
  输入防抖落盘（700ms），关窗与 Esc 前补一次保存；正文随内容加密落盘，磁盘上不出现明文。
  窗口内「全部速记」可切到任意一条。上限 200 条，钉住的不会被容量策略丢掉。
  **明确未做**：富文本 / Markdown、桌面钉住的多显示器跟随、开机自动恢复窗口
- **剪贴板历史（本轮补完整）**：文本 / 图片 / **文件引用**三类都采集；
  每条记录**来源应用与窗口标题**（密码管理器等敏感来源默认排除）；
  同一段文字/同一张图/同一批文件再次复制时**置顶而不是新增**；
  保留期在启动时与修改设置后立即生效；搜索、固定、删除、清空剪贴板记录
- **内容库预览与粘贴（主体补完整）**：点卡片主体打开预览层（图片大图 / 文字全文 /
  文件路径列表），Esc 或点遮罩关闭；卡片可直接**粘贴回打开随序前所在的应用**
  （目标窗口校验失败时如实降级为「已复制，切回目标后粘贴」）
- **区域截图与标注**：**跨屏区域**（覆盖整个虚拟桌面，支持副屏在主屏左侧/上方）、
  混合 DPI，工具为矩形 / 箭头 / 画笔 / 文字 / 马赛克 / 序号，支持撤销、复制 / 保存 / 钉图
- **离线 OCR**：本地 `tesseract.js`，中英文，识别结果可编辑，可**查看原图**
  （原图 = 框选区域未加标注的原始画面）；语言包首次预热约 1–2 秒，之后命中缓存
- **文本处理**：合并换行、清理多余空格、纯文本
- **任务匣**：混合内容、来源标记、派生关系、批量复制、导出 Markdown（已降为低频管理入口）
- **处理轨迹**：按步骤记录每次动作的输入输出与失败原因，**失败记录可一键重试**
- **配方（动作链）**：3 条内置模板，显式提交副作用，支持取消
- **钉图**：置顶窗口、缩放、透明度、临时收起（收成窄条后可点回）、悬停工具栏、
  `Ctrl+Alt+H` 一键显隐
- **内容库**：按类型筛选、搜索、复制、提取文字、钉图、入匣、**固定**（不被自动清理）、
  **清空剪贴板记录**（必须逐字输入确认词才允许提交）、文件条目可直接在资源管理器中定位
- **主窗口记忆（主体补完整）**：记住位置 / 尺寸 / 最大化状态；显示器被拔掉或分辨率变化时
  回落到可见位置，不会让窗口「消失」在已不存在的屏幕上
- **截图流畅度（体验优化）**：覆盖层预热常驻、canvas 走硬件渲染、pointermove 合帧、
  拖动期零强制布局、选区外压暗改 4 块条带；对应 `verify:core` 的预热复用/工具栏时序/合帧断言
- **底部剪贴板历史条（体验优化）**：`Ctrl+Alt+V` 贴底弹出，横向浏览历史图片/文字/文件，
  Enter 复制并尝试粘回原窗口；`test:clipboardbar` 78 项渲染断言
- **设置**：记录开关、保留策略、OCR 语言、敏感来源排除、数据目录、六组快捷键改键、
  **内容加密开关**
- **快捷键冲突检测**：注册失败会显示在设置页并给出原因；支持点击改键，
  改键失败自动回滚到原键位；避开 `Alt+Space` / `Win+V` / `Win+Shift+S` 等系统占用；
  全局键与按住型键位互相冲突时也会拒绝并说明
- **内容加密**：正文与标题用 AES-256-GCM 加密落盘，数据密钥由 Windows DPAPI
  （CurrentUser 范围）保护，换用户或换机器无法解密
- **放回原处（完整链路）**：唤起面板前记录目标窗口（HWND / PID / 进程启动时间），
  提交前重新校验 → 复制 → 置前目标窗口 → `SendInput` 注入 `Ctrl+V`。
  任一步失败都降级为「已复制，切回目标后粘贴」，不假装成功
- **回到桌面 / 锁屏**：`D` / `L` 键位调用系统能力，失败如实报错

### 未实现 / 受限

- **38 键面板中的规划键位**：壁纸、录屏、长截图、改图、日历、Markdown
  保留键位但在面板上标注「未实现」，点击只给提示，不假装可用。
- **速记的边界**：只做纯文本，不做富文本/Markdown；不还原原产品的桌面钉住多屏跟随
  与开机自动恢复窗口（需要位置与显示器的联合记忆，未做）。
- **第三批其余 4 项**：边缘入口、键帽/钉图右键、长截图、录屏
  **尚未开始实现**，差距与证据见 [docs/BATCH3-GAP-ANALYSIS.md](docs/BATCH3-GAP-ANALYSIS.md)。
- **翻译的两个边界**：实时语音翻译（原产品 A 支）未做；图片取词翻译走「截图或已有图片」，
  不支持在已打开的图片上框选局部取词。翻译依赖第三方引擎，离线环境不可用。
- **浮引岛未做部分**：iCloud / 云同步、卡槽编号、跨显示器跟随、QuickLook 式多页预览、
  拖出时的真实「移动」落盘策略。这些需要先观察原产品完整行为再写验收，不以占位宣称完成。
- **按住型侦测的限制**：25ms 轮询会漏掉极短点按（按住语义不受影响）；UAC 安全桌面 / 锁屏
  期间读不到按键，表现为一次「松开」（安全方向）；左右修饰键不区分；每实例常驻一个
  PowerShell 助手（约 30–60MB），不要为多个键位各起一个。
- **`SendInput` 的 UIPI 限制**：普通权限无法向以管理员运行的窗口注入输入
  （[官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)）。
  此时会如实提示「已复制，请手动粘贴」，不会静默失败。产品本身不以管理员常驻。
- **Explorer 右键菜单**：P1 范围，未实现。
- **SQLite**：使用 JSON 文件存储。加密与迁移已实现，但未换成 SQLite 事务。
- **加密搜索范围**：解密后在内存中搜索，不做索引；超出 200 条后搜索会变慢。
- **长截图 / 录屏**：P2 范围，未实现。

## 数据存储

```
%APPDATA%\随序\suira-data.json          内容、任务、执行记录、速记、设置、浮引岛暂存、窗口状态
%APPDATA%\随序\suira-data.key           DPAPI 保护的数据密钥（勿删，删后旧内容无法解密）
%APPDATA%\随序\captures\                截图 PNG
%APPDATA%\随序\clipboard-images\        剪贴板图片
%APPDATA%\随序\tessdata-cache\          OCR 语言包解压缓存（首次识别自动生成）
```

`items[].text` / `items[].title` 在磁盘上是加密信封（`{__enc, iv, data, tag}`），
元数据（id、kind、时间、来源）保持明文以便列表与排序。
内存中始终为明文，因此搜索、派生关系、导出都不需要逐条解密。

浮引岛只保存文件引用（`island.items[] = {id, name, path, kind, addedAt}`）与拖入策略，
不复制文件本体；路径属于元数据，按明文保存。剪贴板文件条目同理：只存路径与文件名，
不复制文件。`windowState` 记录主窗口的位置/尺寸/最大化状态。
速记落在 `notes[] = {id, title, text, createdAt, updatedAt, pinned, bounds}`：
标题与正文跟内容一样加密落盘，`bounds` 是窗口位置记忆（元数据，明文）。

单文件 JSON，版本号 `version: 1`。写入为整体序列化 + 原子 rename，非增量事务。

### 动作协议

所有工具共用一套模型，新增功能不增加新入口：

```text
ContentItem = id + kind + payloadRef + source + createdAt + parentIds
Action      = stableId + acceptedTypes + outputType + executor + sideEffect
Execution   = jobId + inputIds + actionId + status + outputIds + error
Recipe      = id + version + accepts + steps[] + commit
KeyBinding  = key + actionId（lib/keybindings.js 是唯一来源）
ShelfItem   = id + name + path + kind + addedAt（只存引用，lib/island-model.js 负责语义）
QuickNote   = id + title + text + pinned + bounds（标题由正文推导，lib/notes.js 负责语义）
```

关键约束：**动作产出新版本，绝不覆盖原始捕获**。`parentIds` 指回来源，
`meta.derivedBy` 标记由哪个动作生成。38 键面板的每个按键通过 `panel:run`
执行；未实现动作在主进程与渲染层都被拦截，不会假装可用。

### 浮层体系（三个面板共用一套规则）

| 浮层 | 形态 | 何时在屏幕上 |
| --- | --- | --- |
| 浮引岛（文件暂存） | 文件拖入时展开 440×108 / 520×148 | 平时完全隐藏；仅文件拖到屏幕顶部中央才出现，普通悬停不显示 |
| 动作面板（浮卡） | 圆角面板 1160×620、38 个方形键位 | 按 `Ctrl+Alt+Space` 时出现，失焦即隐藏 |
| 剪贴板历史条 | 最大 1600×310 的底部横栏 | `Ctrl+Alt+V`、动作面板 X 键或右下角「剪贴板」按钮打开，失焦即隐藏 |

三条统一约束：

1. **样式只写令牌**。`src/theme.css` 是唯一配色来源，面板 CSS 里不出现具体色值；
   换肤只改 `settings.theme`，主进程写 `nativeTheme.themeSource`，渲染层靠
   `prefers-color-scheme` 自动跟随，没有第二个开关。
2. **窗口比卡片大一圈**。三个浮层都留 12px 阴影留白，卡片用 `inset` 定位，
   阴影才不会被窗口边缘裁掉变成一张"贴死的白片"。
3. **用完归还渲染进程**。Electron 每个窗口都是一个渲染进程，隐藏也占内存；
   常驻的只有浮引岛（它是拖放接收器），动作面板与剪贴板条隐藏 60 秒后销毁，
   下次唤起冷建。

## 已知限制

- 剪贴板监听为 550ms 轮询，非事件驱动（`WM_CLIPBOARDUPDATE` 需原生模块）；
  因此同一份内容连续复制两次不会被再次感知，跨应用复制后约 0.5s 才入库
- 剪贴板文件引用只保存路径与文件名，不复制文件本体；原文件被移动/删除后，
  条目仍可复制路径，但「打开」会如实报错
- OCR 首次识别需要解压并加载语言包，约 1–2 秒；之后命中缓存与常驻 worker 会快很多
- 主进程崩溃会丢失未落盘的会话状态
- 打包配置已包含 OCR 语言包与两个 PowerShell 助手，但尚未做签名与安装验证
- 数据目录不可写时会依次回落到系统临时目录 / 程序同级 `data` 目录，并在自检报告里写明；
  三个位置都不可写才退出（详见 [docs/KNOWN-ISSUES.md](docs/KNOWN-ISSUES.md)）
- 浮引岛缩略图由渲染层按 `file://` 直接加载原图，加载失败回落到类型图标；
  超大图片批量暂存时未做缩略图降采样（后续可改为主进程生成小图）
- 按住型侦测是轮询式：极短点按可能漏掉；UAC 安全桌面 / 锁屏期间读不到按键；
  左右修饰键不区分；非 US 布局下符号键按物理 VK 解释
- 截图覆盖层为了「秒开」改为常驻：隐藏时仍占一个渲染进程（约 40–70MB）；
  如果更在意内存，可以改成闲置 N 分钟后销毁、下次唤起重建
- 底部剪贴板历史条固定出现在**主显示器**工作区底部（多屏时不会跟到光标所在屏）；
  卡片数量上限 60 条，没做搜索框（需要按类型/关键词找旧内容仍用内容库）

## 真实 Electron 验证

**2026-10-22 已在真实 Electron 45 窗口里验证**（不是无头 Chrome 模拟）。
起因是排查启动失败时发现：本机 Electron 无法从工作区内部启动，根因有两个——

1. `ELECTRON_RUN_AS_NODE=1` 让 Electron 以 Node 模式运行（新版会给出中文提示）
2. 工作区目录上有沙箱 ACL 拒绝项（`Everyone: Deny DeleteSubdirectoriesAndFiles`），
   Electron 初始化时触发断点异常，退出码 `0x80000003`

实测同一个 exe 放到工作区外就能正常启动。于是用工作区外的 Electron 加载本项目页面，
